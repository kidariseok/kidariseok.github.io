# Content Guidelines

활동 · 프로젝트 상세 페이지에 **무엇을, 어떤 순서로, 어떤 말투로** 쓰는지 정한 문서입니다.
화면의 모양은 [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md), 작업 순서는 [NEW_ACTIVITY_CHECKLIST.md](NEW_ACTIVITY_CHECKLIST.md)에 있습니다.

표기: **[확인]** 지금 코드와 기존 페이지가 따르는 규칙 · **[신규]** 이번에 정한 규칙(새 활동부터 적용, 기존 페이지 중 벗어난 곳은 [PORTFOLIO_AUDIT.md](PORTFOLIO_AUDIT.md)에 정리) · **[예외]** 허용되는 예외.

이 문서의 규칙 대부분은 `node tools/check-content.mjs` 가 자동으로 확인합니다.

## 1. 이 포트폴리오가 기록하는 것

> 활동 목록을 나열하지 않고, **무엇을 했고 어떤 역할을 맡았는지**를 기록합니다.

| 원칙 | 뜻 |
| --- | --- |
| 역할이 먼저 | 모든 활동은 '그 활동이 무엇인가'보다 '거기서 내가 한 일'을 앞에 둡니다. 요약 패널의 첫 칸이 `MY ROLE` 인 이유입니다. |
| 팀의 일과 내 일을 구분 | 팀 성과를 내 성과처럼 쓰지 않습니다. 팀이 한 일은 '팀'으로, 내가 한 일은 '내가 한 일'로 나눠 씁니다 (`{roles}` 블록, 발표자료의 `pm`). |
| 확인되는 숫자만 | 숫자에는 근거가 있어야 합니다(확인서, 설문, 저장소, 기록). 근거를 괄호로 붙입니다: `봉사 177시간 (1365 확인서)`. 어림값에는 `약`을 붙입니다. |
| 잘 안 된 것도 적는다 | 탈락 · 무산 · 아쉬운 점을 숨기지 않습니다 (예: SKKU-BA-DIVE '최종 미선발', RE:ALThon '06. 아쉬웠던 점'). |
| 배운 것으로 끝낸다 | 기록형 페이지는 마지막에 '돌아보며'를 둡니다. 무엇이 달라졌는지를 씁니다. |
| 모르면 비워 둔다 | 확인하지 못한 값을 지어내지 않습니다. 그 칸을 빼거나 `[확인 필요] …` 로 표시합니다(7.5). |

## 2. 데이터가 있는 곳

활동 하나는 **세 파일에 같은 `id` 로** 나뉘어 있습니다.

| 파일 | 담는 것 | 활동 관련 항목 |
| --- | --- | --- |
| `content/common.js` | 언어와 상관없는 값 | `activities`(id · 날짜 · 구분) · `photos` · `decks` · `projects` · `featured` · `archiveReps` |
| `content/ko.js` | 한국어 글자 | `activities[id]` |
| `content/en.js` | 영어 글자 | `activities[id]` (ko.js 와 같은 모양) |
| `img/` · `video/` | 사진 · 슬라이드(.webp) · 영상(.mp4) | 8장 |

**id 규칙** [확인]

- 영문 소문자 · 숫자 · 하이픈: `freemed`, `ktng-overseas`, `trade-ai`.
- 주소(`#a/id`)가 되므로 **한 번 공개한 뒤에는 바꾸지 않습니다.** 바꿔야 하면 `index.html` 의 `LEGACY_IDS` 에 옛 이름을 등록합니다.
- 단체 · 행사 이름을 짧게 씁니다. 연도는 같은 이름의 활동이 둘 이상일 때만 붙입니다.

## 3. 활동 구분 (category)

기준은 하나입니다: **그 활동에서 내가 주로 한 일.** 주최 기관의 성격이나 행사 이름으로 정하지 않습니다. [확인 — `common.js` 의 `categories` 주석]

| 값 | 화면 이름 (KO / EN) | 내가 주로 한 일 | 기존 예 |
| --- | --- | --- | --- |
| `project` | 프로젝트 · 해커톤 / Projects & Hackathons | 무언가를 **기획하거나 만든** 활동. 결과물(서비스, 기획서, 발표자료)이 남음 | 2GATHER, 지금 우리 율전은, 무역 인공지능 캠프, ICISTS, BA-DIVE, S-Global |
| `community` | 커뮤니티 · 운영 / Community & Organizing | 동아리 · 행사를 **운영하거나 학교를 대표한** 활동 | RE:ALThon, GDG on Campus, 멋쟁이사자처럼, 크레버스, CHED 방문단 |
| `edu` | 교육 · 봉사 / Teaching & Service | **가르치거나 도운** 활동 | KT&G 해외봉사, 프리메드, 스피치 멘토단, 오디바이스, 드림온, 월드비전 |
| `learn` | 학습 · 탐색 / Learning & Exploring | **듣고 보고 배운** 활동. 참가자 · 수강생 · 관람객 | 에듀테크 박람회, 미래기술과정, 국제학술지 특강 |

**헷갈릴 때** [신규]

1. 여러 일을 했다면 **시간을 가장 많이 쓴 일**로 정합니다.
2. 해커톤에 **참가해서 만들었으면** `project`, 해커톤을 **열고 운영했으면** `community`.
3. 동아리에서 **프로젝트 하나가 중심**이면 그 프로젝트를 별도 활동(`project`)으로 만들고, 동아리 활동은 `community` 로 따로 둡니다 (예: `line4` 와 `likelion12`). 두 페이지는 요약 패널의 `links` 로 서로 잇습니다.
4. 공모전에 지원했으나 떨어진 것도 계획서 · 발표자료를 만들었으면 `project`.
5. 구분은 4개로 고정입니다. 새 구분을 만들지 않습니다.

## 4. 페이지 유형

상세 페이지의 **뼈대는 모두 같습니다**(상단 블록 → 요약 패널 → 사진 → 영상 → 발표자료 → 본문 → 이전/다음). 달라지는 것은 본문의 깊이와 붙는 자료뿐입니다. 활동을 추가하기 전에 아래 세 유형 중 하나를 고릅니다. [신규 — 기존 20개 페이지를 분류해 정리]

| | **A. 프로젝트** | **B. 기록** | **C. 간단 기록** |
| --- | --- | --- | --- |
| 언제 | 직접 기획 · 제작한 결과물이 있고 대표로 내세울 것 | 과정과 배운 점을 여러 장면으로 풀어 쓸 것 | 사실 위주로 짧게 남길 것 |
| 요약 패널 | `proj` (역할 · 기술이 칩으로) | `panel` | `panel` |
| 본문 소제목 | 5–10개, 번호 작은 제목 필수 | 4–11개, 번호 작은 제목 필수 | 1–2개, 번호 없음 |
| 목차 | 자동 생성 | 자동 생성 | 없음 |
| 본문 분량 (한국어, 공백 포함) | 2,000–5,000자 | 1,300–8,000자 | 300–1,200자 |
| 자료 | 영상 또는 발표자료 중 하나 이상 | 사진 · 발표자료 · 이수증 등 있는 대로 | 있으면 표지 · 사진 |
| 메인 노출 | `projects` (프로젝트 카드) | 필요하면 `featured` 또는 `archiveReps` | 활동 기록 목록 |
| 기존 예 | `line4`, `goormthon` | `freemed`, `ktng-overseas`, `realthon`, `gdsc`, `edutech-expo`, `trade-ai`, `ba-dive`, `future-tech`, `intl-publication`, `creverse`, `dreamon` | `audivice`, `worldvision`, `likelion12`, `icists`, `ched`, `speech-mentors`, `s-global` |

**의도적으로 다른 것과 통일해야 하는 것**

| 유형에 따라 달라도 되는 것 [확인] | 모든 유형에서 같아야 하는 것 [확인] |
| --- | --- |
| 요약 패널이 `proj` 인지 `panel` 인지 (프로젝트만 역할 · 기술이 칩) | 구역의 순서와 간격 |
| `STACK` · `MY TOOLS` 칸 (프로젝트만) | 요약 패널의 칸 순서와 라벨 |
| 본문 분량과 소제목 수, 목차 유무 | 제목 → 소속 → 요약의 순서, 날짜는 `PERIOD` 한 곳 |
| 사진 · 영상 · 발표자료의 유무 | 요약(summary)의 말투와 길이 |
| 메인 화면에서의 카드 종류 | 본문 블록의 모양, 마지막 '돌아보며' |

## 5. 항목 스키마

### 5.1 `common.js` — `activities` 의 한 줄

```js
{id:"새id", start:"2026-10-01", end:"2026-12-20", category:"project", notion:""}
```

| 키 | 필수 | 형식 | 설명 |
| --- | --- | --- | --- |
| `id` | ● | kebab-case | 2장의 규칙 |
| `start` | ● | `"YYYY-MM-DD"` | 시작일. **배열 정렬 기준** |
| `end` | | `"YYYY-MM-DD"` | 끝난 날. 하루짜리면 뺍니다 |
| `dates` | | `["YYYY-MM-DD", …]` | 떨어진 여러 날을 모두 보여 줄 때 (예: 2024 · 2026 두 번 방문). 있으면 `start`/`end` 대신 표시 |
| `noDate` | | `true` | 날짜를 화면에 표시하지 않음. 지원일처럼 날짜가 의미 없을 때 (정렬에는 `start` 사용) |
| `category` | ● | `project` / `community` / `edu` / `learn` | 3장 |
| `notion` | | 문자열 | 원본 기록 페이지 id. 화면에는 쓰지 않습니다. 없으면 `""` |
| `video` | | `https://…` | **외부** 영상 주소(YouTube). 상세 제목 아래 '활동 영상' 버튼이 생김. 직접 올린 mp4 는 8.3 |

- [확인] `activities` 배열은 **`start` 가 늦은 것이 위**입니다. 이 순서가 활동 기록 목록과 '이전 / 다음 활동'의 순서가 됩니다.
- [확인] 날짜는 자동으로 바뀌어 표시됩니다. 하루: `2024.07.17` / `Jul 2024` · 같은 달 여러 날: `2024.12.06 - 12.07` / `6–7 Dec 2024` · 여러 달: `2024.03 - 2025.03` / `Mar 2024 - Mar 2025`.

### 5.2 `ko.js` / `en.js` — `activities[id]`

| 키 | 필수 | 길이 (KO / EN) | 화면에 나오는 곳 |
| --- | --- | --- | --- |
| `title` | ● | 25자 / 55자 이하 | 상세 `h1`, 모든 목록, 이전/다음 |
| `org` | | 20자 / 45자 이하 | 제목 아래 소속 한 줄, 대표 활동 카드, 프로젝트 카드 |
| `summary` | ● | 40–110자 / 80–260자 | 상세 제목 아래 요약(lede) |
| `short` | ○ | 70자 / 120자 이하 | 목록용 한 줄. 없으면 `summary` 를 씁니다 |
| `panel` | ● (유형 B · C) | 5.3 | 상세 요약 패널, 활동 기록 목록의 설명(`panel.role`) |
| `proj` | ● (유형 A) | 5.4 | 프로젝트 카드, 상세 요약 패널 |
| `card` | `featured` 일 때 ● | 5.5 | 대표 활동 카드 |
| `vid` | 영상이 있을 때 ● | 5.6 | 영상 구역의 설명 |
| `deck` | 발표자료가 있을 때 ● | 5.7 | 발표자료 구역 |
| `photosTitle` | | 12자 / 25자 이하 | 사진 줄 제목을 '현장 사진' 대신 바꿀 때 (예: '교내 기사 화면 캡처') |
| `body` | ● | 4장의 분량 | 본문 (6장의 블록 배열) |

**`title` 과 `org`** [확인]

- 기본: `title` = **활동(단체 · 행사)의 공식 이름**. `org` 는 비웁니다. 예: `프리메드`, `KT&G 상상위더스 해외봉사단`.
- 유형 A, 또는 행사 이름이 단체 이름보다 널리 알려진 경우: `title` = **프로젝트 · 행사 이름**, `org` = **그것을 한 단체 · 대회**. 예: `2GATHER` / `멋쟁이사자처럼 4호선톤`, `RE:ALThon` / `GDG on Campus : SKKU`.
- [신규] 제목에 내 역할이나 수식어를 넣지 않습니다(`…총괄`, `…참가 후기` ✕). 역할은 `panel.role` 에 씁니다.
- [예외] 탈락한 공모전은 제목 끝에 `도전` / `application` 을 붙입니다 (`SKKU-BA-DIVE 도전`).

**`summary`** — 이 활동을 한 문단으로 [확인]

- **무엇을 했는지 + 내 역할 + (있으면) 핵심 숫자**를 1–2문장에 담습니다.
- 한국어는 `~함.` 으로 끝냅니다. 예: `인도네시아 보고르 지역 초등학교에 파견되어 177시간 동안 교육, 환경 개선 봉사를 함.`
- 영어는 주어 없이 과거형 동사로 시작합니다. 예: `Deployed to an elementary school in Bogor, Indonesia for 177 hours of education and environmental-improvement volunteering.`
- 감상 · 배운 점은 쓰지 않습니다(본문 마지막에).

**`short`** — 목록용 한 줄 [확인]

- `summary` 를 한 줄로 줄인 것. 한국어는 `~함` 으로 끝내고 **마침표를 붙이지 않습니다.** 영어는 마침표 없이 명사구 또는 과거형.
- [신규] `summary` 가 KO 70자 / EN 120자 이하이면 `short` 를 생략해도 됩니다. 넣을 때는 **두 언어 모두** 넣습니다.

### 5.3 요약 패널 — `panel`  <a id="5-요약-패널-메타데이터"></a>

상세 페이지 맨 위 표. 칸 순서는 고정이고 값이 없는 칸은 나오지 않습니다. [확인]

```js
panel: {
  role: "방문건강관리팀 30기 단원 → 돈의동 쪽방촌 파트장 · 팀 스터디장 · MD 동행 사업 기획",
  team: "방문건강관리팀 약 14명 (사업 3개) · 돈의동 사업 단원 2–3명",
  period: "2024.03 – 2025.03",
  where: "사단법인 프리메드 · 서울 종로구 돈의동 쪽방촌 (협력기관 새뜰집)",
  result: "방문 17회 · 24시간 10분 (1365 확인서) · 사업 기록지 12건 · 회의록 9건 작성",
  key: "17회 방문",
  links: [{t:"이어진 해외봉사 보기", href:"#a/ktng-overseas"}]
}
```

| 키 | 라벨 | 필수 | 무엇을 쓰나 | 쓰지 않는 것 | 길이 (KO) |
| --- | --- | --- | --- | --- | --- |
| `role` | MY ROLE | ● | **내가 맡은 직책과 한 일.** 직책 → 한 일 순서, ` · ` 로 나열. 직책이 바뀌었으면 `→` | 팀 전체가 한 일, 얻은 것(`인사이트를 얻음` ✕), 문장형 서술 | 15–60자 |
| `team` | TEAM | | **함께한 사람의 수와 구성.** `6인 팀 (기획 1 · FE 3 · BE 2)`, `해외봉사단 40명 (4개 조)` | 팀원 이름 | 40자 이하 |
| `scale` | SCALE | | **활동의 크기.** 참가자 · 대상 인원 · 횟수 · 시간. `참가자 50명 · 9개 팀`, `강좌 14개 · 총 14시간` | 성과(→ `result`) | 40자 이하 |
| `period` | PERIOD | | 날짜에 **설명을 덧붙일 때만** 직접 씁니다: `2024.12.06 – 12.07 · 무박 2일`. 비우면 `common.js` 날짜가 자동으로 나옵니다 | 날짜만 다시 적기 | 40자 이하 |
| `where` | WHERE | | **주최 기관 · 장소.** `주최 · 장소` 순서. 필요하면 `(…)` 로 보충 | 활동 설명, 내 역할 | 50자 이하 |
| `result` | RESULT | | **남은 결과.** 숫자, 산출물, 선발 여부, 보도. 근거를 괄호로 | 감상, 배운 점 | 60자 이하 |
| `key` | (큰 숫자) | | `result` 중 **가장 중요한 숫자 하나.** `177시간`, `17회 방문`, `약 700만 원대`. `result` 가 있을 때만 나옵니다 | 숫자가 아닌 말, 두 개 이상의 숫자 | 10자 이하 |
| `links` | (버튼) | | `[{t:"글자", href:"주소"}]`. 바깥 링크(`https://`) 또는 다른 활동(`#a/id`) | 영상 · 발표자료 이동(자동으로 붙음) | 버튼 3개 이하 |

**칸을 고르는 기준** [신규]

- `role` 은 항상 씁니다. 활동 기록 목록의 한 줄 설명도 이 값을 씁니다.
- `scale` 과 `result` 를 헷갈리면: **활동이 원래 그 크기였으면 `scale`, 내가(우리가) 해서 생긴 것이면 `result`.** 내 봉사 시간은 `result` 입니다.
- `where` 는 '어디서'와 '누가 주최했나'를 함께 답합니다. `title` 이 이미 기관 이름이면 장소만 써도 됩니다.
- `key` 는 페이지에서 가장 크게 보이는 숫자가 됩니다. 자랑할 숫자가 없으면 넣지 않습니다.
- 칸은 **3개 이상**을 목표로 합니다. `PERIOD` 한 칸만 있는 패널은 비어 보입니다.
- 한 칸에 34자가 넘으면 두 칸 폭으로 넓어집니다. 여러 칸이 넓어지면 표가 들쭉날쭉해지므로 값을 짧게 씁니다.

### 5.4 프로젝트 — `proj`

유형 A 에서 `panel` 대신 씁니다. 메인 화면의 프로젝트 카드와 상세 요약 패널이 같은 값을 씁니다. [확인]

```js
proj: {
  name: "2GATHER",
  type: "AI · 웹 서비스",
  what: "대학생과 초기 창업자가 적은 예산과 제한된 네트워크로도 홍보 계획을 세우고, 필요한 사람과 연결되도록 돕는 AI 홍보 전략 플랫폼",
  role: ["PM", "UX/UI 기획", "PRD 작성", "서비스 구조 설계"],
  tools: ["Figma"],
  team: "6인 팀 (기획·PM 1 · UI 디자인 1 · FE/BE 4)",
  period: "2024.10.06 – 11.16 · 6주 (본선 11.16)",
  result: "6주 만에 서비스 배포",
  key: "6주",
  stack: ["React", "Spring Boot", "OpenAI API", "MySQL"],
  links: [{t:"GitHub · Front-end", href:"https://github.com/…"}]
}
```

| 키 | 필수 | 설명 | 기준 |
| --- | --- | --- | --- |
| `name` | ● | 프로젝트 이름 (카드의 큰 제목) | 보통 `title` 과 같게 |
| `type` | ● | 종류 알약. `분야 · 형태` | 2단어, 15자 이하 |
| `what` | ● | 누구의 어떤 문제를 어떻게 푸는지 한 문단 | 60–110자, 명사형 또는 `~습니다` |
| `role` | ● | 내 역할 칩 (배열) | 2–4개, 각 12자 이하 |
| `tools` | | **내가 직접 쓴** 도구 (배열). 있으면 `STACK` 라벨이 'STACK · 팀 개발'로 바뀌어 팀의 기술과 구분됩니다 | 1–3개 |
| `team` | ○ | 팀 구성 | `panel.team` 과 같은 형식 |
| `period` | ○ | 기간 + 설명 | `panel.period` 와 같은 형식 |
| `result` | ○ | 결과 한 줄 | 30자 이하 (카드에도 나옴) |
| `key` | | 핵심 숫자 | 10자 이하 |
| `stack` | ● | 기술 칩 (배열). 저장소에서 확인되는 것만 | 3–5개 |
| `links` | ○ | 저장소 · 서비스 주소 | 버튼 글자는 `GitHub · Front-end` 형식 |

- 유형 A 에 `where` · `scale` 이 필요하면 `panel` 을 **함께** 두고 그 두 키만 넣습니다.
- `proj.date` 는 예전 항목이며 화면에 쓰이지 않습니다. 새로 넣지 않습니다.

### 5.5 대표 활동 카드 — `card`

`common.js` 의 `featured` 에 든 활동만 필요합니다. [확인]

```js
card: {role:"인사 총괄(Core) · 월간 IT 세미나 연사 섭외", result:"정기 세미나를 열어 한 해 동안 300명의 학생에게 강의를 제공함"}
```

- `role`: `panel.role` 을 카드용으로 줄인 것. KO 45자 / EN 90자 이하.
- `result`: 한 줄 성과. KO 60자 / EN 130자 이하. 한국어는 `~함` · `~쌓음` · `~얻음` 으로 끝내고 **마침표를 붙이지 않습니다.**
- 휴대폰에서는 이 두 줄만 12.5px 로 보이므로 짧을수록 좋습니다.

### 5.6 영상 설명 — `vid`

`common.js` `photos[id].video` 가 있을 때 필요합니다. [확인]

```js
vid: {k:"PROMO VIDEO", t:"2GATHER 공식 프로모션 영상", d:"영상에 무엇이 담겼는지 2–3문장.", pm:"PM으로서 스토리라인을 구성하고 PRD를 작성했습니다."}
```

| 키 | 필수 | 설명 |
| --- | --- | --- |
| `k` | ○ | 영문 대문자 작은 제목. `PROMO VIDEO` · `SKETCH VIDEO` · `DEMO VIDEO` 중에서 |
| `t` | ● | 영상 제목 |
| `d` | ● | 무엇이 담겼는지 2–3문장 (`~입니다`) |
| `pm` | | 이 영상에서 '내가 한 일' 한 문장. 내가 만든 것이 아니면 넣지 않습니다 |

### 5.7 발표자료 — `deck`

`common.js` `decks[id]` 와 짝입니다. [확인]

```js
deck: {
  title: "발표자료",
  chapters: [
    {name:"소개", pm:"이 장에서 내가 한 일 한 문장.", slides:[
      {k:"INTRO", t:"홍보전략 플랫폼, 2GATHER", d:"이 슬라이드가 말하는 것 1–3문장."}
    ]},
    {name:"문제 정의", slides:[ … ]}
  ]
}
```

- `title`: `발표자료`(내가 발표) 또는 `팀 발표자료`. 영어는 `Pitch deck` / `Presentation` / `Team presentation`.
- `chapters`: 3–6개. `name` 은 6자 이하(칩에 들어감).
- `pm`: 그 장을 **내가 맡았을 때만** 씁니다. 맡지 않은 장에는 넣지 않습니다 — 이 유무가 내 기여 범위를 보여 줍니다.
- `slides`: 장 순서대로 1번부터 이어집니다. **모든 장의 슬라이드 수 합 = `decks[id].count`** 여야 합니다(다르면 뒤쪽이 화면에서 빠집니다).
- 슬라이드 한 장: `k` 영문 대문자 작은 제목(2–3단어) · `t` 제목(25자 이하) · `d` 설명 1–3문장. `d` 는 슬라이드를 읽어 주는 것이 아니라 **왜 이 장이 있는지**를 씁니다.

## 6. 본문 블록 사전  <a id="6-본문-블록-사전"></a>

`body` 는 블록의 배열입니다. **블록 하나에는 한 종류만** 넣습니다. 아래 19종 외에는 화면에 나오지 않습니다. [확인 — `index.html` `renderDetail()`]

### 6.1 글

| 블록 | 문법 | 언제 | 기준 |
| --- | --- | --- | --- |
| 소제목 | `{k:"01 · 문제", h:"좋은 아이디어가 있어도, 알릴 방법이 없었습니다.", toc:"01 문제"}` | 본문을 장면 · 주제로 나눌 때. 3개 이상이면 목차가 생김 | 7.2 |
| 작은 소제목 | `{h3:"1일차 · 선전"}` | 한 소제목 안을 다시 나눌 때. 목차에 안 들어감 | 20자 이하 |
| 첫 문장 | `{lead:"2주에 한 번, 같은 분을 찾아가는 일"}` | **본문 맨 처음 한 번.** 이 활동을 한 줄로 | 40자 이하. 유형 A · B 에만 |
| 문단 | `{p:"…"}` | 기본 서술 | 한 문단 1–3문장, 150자 이하 권장 |
| 강조 문장 | `{q:"…"}` | 그 소제목의 결론 한 문장 | 소제목당 1개 이하, 80자 이하. 남의 말 인용이 아니라 **내 결론** |
| 참고 상자 | `{note:"…"}` | 본문 흐름 밖의 보충: 출처, 개인정보 처리 안내, 용어 설명 | 페이지당 1–2개 |

### 6.2 목록 · 나열

| 블록 | 문법 | 언제 | 기준 |
| --- | --- | --- | --- |
| 목록 | `{ul:["<b>이름</b>: 설명", …]}` | 순서 없는 항목 3–6개 | 항목 앞에 `<b>이름</b>:` 를 두면 훑어 읽기 좋습니다 |
| 체크 목록 | `{checks:[…]}` | '알게 된 것 · 해낸 것'처럼 완료의 의미가 있을 때 | 3–5개 |
| 정보 칩 | `{facts:["2024.03 – 2025.03", "월 2회 · 토요일 오후"]}` | 짧은 사실 3–5개를 한 줄로 | 칩 하나 18자 이하 |
| 흐름 | `{flow:["입력", "분석", "추천"]}` | 순서가 있는 단계 3–5개 | 단계 하나 10자 이하 |
| 회색 상자 | `{boxes:["문제 1", "문제 2"]}` | 같은 무게의 짧은 문장 2–4개 (문제점, 조건) | 짝수 개. 상자 하나 40자 이하 |

### 6.3 숫자 · 비교

| 블록 | 문법 | 언제 | 기준 |
| --- | --- | --- | --- |
| 숫자 | `{stat:[{k:"목표", v:"30명"}, {k:"실제 모집", v:"9명", hi:true}]}` | 숫자 2–3개를 나란히. 사이에 `→` 가 붙으므로 **변화 · 대비**에 씁니다 | 3개 이하. `hi:true` 는 강조할 하나에만 |
| 카드 | `{cards:[{n:"READING", t:"제목", d:"설명"}, …]}` | 같은 틀의 항목 2–4개 (기능, 이론, 인사이트) | **한 블록에 2–4장.** 6개면 3 + 3 으로 블록을 나눕니다. `n` 은 영문 대문자 또는 번호 |
| 두 칸 비교 | `{cmp:[{n:"2024", t:"…", d:"…"}, {n:"2026", t:"…", d:"…"}]}` | 전 / 후, A / B. **오른쪽 칸이 검게 강조**되므로 결론 · 나중 것을 오른쪽에 | 정확히 2칸 |

### 6.4 역할

| 블록 | 문법 | 언제 | 기준 |
| --- | --- | --- | --- |
| 팀 구성 | `{people:[{role:"기획 · PM", n:1, me:true, note:"나"}, {role:"프론트엔드", n:3}], note:"…"}` | 팀이 몇 명이고 내가 어디였는지 | `me:true` 는 한 곳. 팀원 이름은 8.6 의 기준을 따릅니다 |
| 팀 / 내가 한 일 | `{roles:{tl:"TEAM", ml:"MY CONTRIBUTION", team:["…"], mine:["…"]}}` | 팀 전체의 일과 내 일을 나란히 | 유형 A 는 필수. 각 3–5항목 |

### 6.5 자료

| 블록 | 문법 | 언제 | 기준 |
| --- | --- | --- | --- |
| 문서 이미지 | `{cert:{img:"future_tech_cert", alt:"…이수증", cap:"이수증 (2024.02.23)"}}` | 이수증 · 상장 · 확인서 같은 세로 문서 한 장 | `alt` 필수. 번호 · 주민번호 · 서명은 가립니다(8.5) |
| 첨부 | `{files:["파일이름.pdf"]}` | 파일 이름만 나열 (내려받기 링크 아님) | 꼭 필요할 때만 |
| 링크 | `{link:"GitHub · Front-end", href:"https://…"}` | 본문 흐름 안의 바깥 링크. `#a/id` 면 같은 탭에서 다른 활동으로 | 주요 링크는 `panel.links` 에. `https://` 만 |

### 6.6 글자 안에 쓸 수 있는 표시

- `<b>굵게</b>`: `p` · `lead` · `q` · `note` · `ul` · `checks` · `boxes` · `cards`/`cmp` 의 `d` · `roles` 항목에서 쓸 수 있습니다. 문단당 한 군데, **그 문단에서 꼭 읽혀야 할 구절**에만.
- `<br>`: `note` 안에서 줄을 나눌 때만.
- [신규] 그 밖의 HTML 태그 · 인라인 스타일 · 이모지는 쓰지 않습니다. 본문 안에서 다른 활동으로 잇는 것은 `{link}` 블록이나 `panel.links` 를 씁니다.
- 큰따옴표는 `“ ”` 를 쓰거나 `\"` 로 씁니다.

## 7. 구성과 문체

### 7.1 본문의 순서

**유형 A — 프로젝트** [확인: `line4` 가 기준]

| 순서 | 내용 | 주로 쓰는 블록 |
| --- | --- | --- |
| 도입 | 한 줄 정의 + 무엇을 · 누구와 · 얼마 동안 | `lead` `p` `p` |
| 01 · 문제 | 어떤 경험에서 문제를 발견했나 | `p` `stat` `boxes` `q` |
| 02 · (프로젝트 이름) | 해결 방법 한 문단 + 핵심 기능 | `p` `cards` |
| 03 · 어떻게 작동할까 | 사용자가 거치는 흐름 | `p` `flow` |
| 04 ~ · 핵심 설계 | 설계에서 내린 판단 1–3개 | `p` `cards` `cmp` |
| 0N · 내가 한 일 | 팀 구성과 내 기여 | `people` `roles` |
| 0N · 기술 구성 | 저장소로 확인되는 구성 | `cards` `link` |
| 0N · 결과 | 무엇이 남았나 | `p` `q` |
| 0N · 돌아보며 | 배운 것과 다음에 다르게 할 것 | `p` `q` |

**유형 B — 운영 · 커뮤니티** [확인: `realthon`, `gdsc`]

`01 상황` → `02 판단` → `03 실행` → `04 예산 · 자원(또는 한 일의 목록)` → `05 결과` → `06 아쉬웠던 점` → `07 배운 것` → `08 이후의 변화` → `돌아보며`

**유형 B — 교육 · 봉사** [확인: `freemed`, `ktng-overseas`]

도입(`lead` · `p` · `facts`) → `01 시작(왜 하게 됐나)` → `02 맡은 역할` → `03–0N 현장의 장면들` → `0N 배운 것` → `0N 돌아보며`. 개인정보를 가렸다면 도입 끝에 `{note}` 로 알립니다.

**유형 B — 학습 · 탐색** [확인: `edutech-expo`, `future-tech`, `intl-publication`]

도입(`lead` · `p`) → `01–0N 인사이트 하나에 소제목 하나`(무엇을 봤나 → 내가 읽어 낸 것) → `0N 돌아보며(내 방향과의 연결)`. 강의 내용을 받아 적지 않고 **내가 정리한 관점**을 씁니다.

**유형 C — 간단 기록** [확인: `audivice`, `worldvision`]

```js
body: [
  {h:"주요 성과"},
  {ul:["<b>한 일 1</b>: 설명", "<b>한 일 2</b>: 설명"]},
  {h:"돌아보며"},
  {p:"무엇을 느꼈고 무엇이 달라졌는지 한두 문단."}
]
```

### 7.2 소제목 쓰는 법

지금 기존 페이지에는 네 가지 방식이 섞여 있습니다([AUDIT C-01](PORTFOLIO_AUDIT.md)). **새 활동은 아래 두 가지 중 하나만** 씁니다. [신규]

**유형 A · B (소제목 3개 이상)** — 번호 작은 제목 + 문장형 제목

```js
{k:"01 · 문제", h:"좋은 아이디어가 있어도, 알릴 방법이 없었습니다."}
{k:"05 · MD 동행", toc:"05 MD 동행", h:"의사 선생님과 함께 가자고 제안했습니다."}
```

- `k`: `두 자리 번호 · 이름`. 이름은 8자 이하 명사. **그 페이지의 언어로** 씁니다(한국어 페이지에 `01 · Problem` ✕ → `01 · 문제`).
- `h`: 그 장면의 요점을 **한 문장**으로. `~습니다.` 로 끝내고 35자 이하.
- `toc`: 목차에 들어갈 이름. `k` 가 길면 줄여서 넣습니다(KO 16자 / EN 24자 이하). 비우면 `k` 가 그대로 쓰입니다.
- 번호는 01 부터 빠짐없이 이어집니다. 마지막 소제목까지 번호를 붙입니다.
- 한 페이지 안에서 `{k:"01 · 이름"}` 방식과 `"01. 이름: …"` 방식을 섞지 않습니다.

**유형 C (소제목 1–2개)** — 번호 없는 명사형. 소제목이 3개가 되면 목차가 생기므로, 3개 이상 필요하면 유형 B 로 씁니다

```js
{h:"주요 성과"}   {h:"돌아보며"}
```

**마지막 소제목의 이름** [신규]: 배운 점 · 소감을 쓰는 마지막 소제목은 한국어 **`돌아보며`**, 영어 **`Looking back`** 으로 통일합니다 (`소감` · `무엇을 배웠는가` · `Reflection` · `What I Learned` 는 기존 표기이며 새로 쓰지 않습니다).

### 7.3 말투

| 자리 | 한국어 | 영어 |
| --- | --- | --- |
| `summary` | 명사형 종결 `~함.` (마침표 있음) | 주어 없는 과거형 문장. 마침표 있음 |
| `short` · `card.result` | `~함` (마침표 없음) | 명사구 또는 과거형. 마침표 없음 |
| `panel` · `proj` 의 값 | 명사구. ` · ` 로 나열 | 명사구. ` · ` 로 나열 |
| 본문 `p` · `q` · `lead` · `h` | 합쇼체 `~했습니다`, `~였습니다` | 1인칭 과거형 (`I proposed…`, `We cut down…`) |
| `ul` 항목 | `<b>이름</b>: ~했습니다.` 또는 명사형 | 같은 구조 |
| `deck` · `vid` 의 `d` | `~입니다`, `~했습니다` | 현재형 · 과거형 문장 |

- [확인] 1인칭은 **'저'**, 팀은 '저희' 또는 '팀'. '필자' · '본인' 은 쓰지 않습니다.
- [확인] 과장하는 말을 쓰지 않습니다: `성공적으로`, `완벽하게`, `압도적`, `혁신적` ✕. 숫자와 사실로 말합니다.
- [확인] 본문은 **장면 → 판단 → 결과** 순서로 씁니다. "~를 배웠습니다"만 쓰지 말고 무엇을 보고 그렇게 생각했는지를 앞에 둡니다.
- [신규] 한 문단은 3문장을 넘기지 않습니다. 길어지면 문단을 나누거나 `ul` · `cards` 로 바꿉니다.

### 7.4 표기

| 항목 | 규칙 | 예 |
| --- | --- | --- |
| 나열 구분 | 가운뎃점 앞뒤에 공백 ` · ` (메타데이터). 한 낱말 안에서는 붙여서 `·` | `팀장 · 스피치 멘토링` / `회계·물품팀` |
| 범위 | 반각 줄표 `–` (en dash). 한국어 날짜는 앞뒤 공백, 숫자 범위는 붙여서 | `2024.03 – 2025.03` / `20–30명` |

| 날짜 (EN) | `D Mon YYYY`, 일 – 월 – 연 순서 | `6 Oct – 16 Nov 2024`, `Oct 2024 – Feb 2025` |
| 수 | 아라비아 숫자 + 단위 붙여 쓰기. 어림값은 `약` / `about` | `177시간`, `약 14명`, `50 participants` |
| 금액 (KO) | `약 700만 원대`, `2,824,500원` | |
| 금액 (EN) | `KRW 7 million` (`₩` 를 섞어 쓰지 않습니다) | |
| 근거 | 숫자 뒤 괄호 | `봉사 177시간 (1365 확인서)` |
| 단체 이름 | 공식 표기 그대로. 한 번 정하면 모든 곳에서 같게 | `GDG on Campus : SKKU` (콜론 앞뒤 공백), `KT&G 상상위더스` |
| 영어 약어 | 처음 나올 때 풀어 씁니다 | `필리핀 대통령실 고등교육위원회(CHED)` |

### 7.5 확인되지 않은 값

값이 **`[확인 필요`** (영어 **`[To confirm`**) 로 시작하면 점선 칩 · 기울임으로 표시됩니다(`isTbd`). 초안을 쓰는 동안에만 쓰고, **배포 전에는 확정하거나 그 항목을 지웁니다.** 검증 스크립트가 남아 있는 개수를 알려 줍니다.

```js
stack: ["React", "[확인 필요] 백엔드 프레임워크"]
```

## 8. 사진 · 영상 · 발표자료

### 8.1 파일 규칙 [확인]

- 사진과 슬라이드는 **`.webp` 만** 씁니다. 코드가 이름 뒤에 `.webp` 를 붙여 불러옵니다(`imgSrc`). `common.js` 에는 **확장자 없이** 이름만 적습니다.
- 이름은 영문 소문자 · 숫자 · 밑줄: `접두어_종류_번호`.

| 종류 | 이름 | 크기 | 용량 | 비율 |
| --- | --- | --- | --- | --- |
| 표지 | `접두어_cover` | 긴 변 1400px | 250KB 이하 | **가로 16:9 – 3:2 권장** |
| 현장 사진 | `접두어_01`, `_02` … | 긴 변 1400px (최소 900px) | 250KB 이하 (한도 400KB) | 자유 (목록에서는 4:3 으로 잘려 보임) |
| 슬라이드 | `접두어_slide_01` … | 1440×810 (16:9) | 장당 100KB 이하 | 16:9 고정 |
| 영상 포스터 | `접두어_video_poster` | 1280×720 | 100KB 이하 | 16:9 고정 |
| 문서 이미지 | `접두어_cert` 등 | 긴 변 1500px | 150KB 이하 | 세로 |
| 영상 | `video/이름-kebab.mp4` | 1280×720, H.264 | **40MB 이하** | 16:9 |

- 접두어는 활동마다 하나로 정합니다(`freemed`, `ktng`, `line4`). id 와 같지 않아도 되지만 한 활동의 파일은 같은 접두어를 씁니다.
- 번호는 두 자리(`01`). 슬라이드는 **01 부터 빠짐없이** 이어져야 합니다.

### 8.2 표지와 사진 줄

```js
// common.js
photos: {
  freemed: {cover:"freemed_04", shots:["freemed_01", "freemed_03", "freemed_02", "freemed_05", "freemed_04"]}
}
```

- **표지(`cover`)**: 상세 제목 옆(380px 칸), 대표 활동 카드의 오른쪽에 나옵니다. 최대 높이 440px 에서 가운데 기준으로 잘립니다.
  - [신규] 가로형을 고릅니다. 세로형은 휴대폰에서 화면 대부분을 차지해 제목이 밀려납니다([AUDIT A-11](PORTFOLIO_AUDIT.md)).
  - 활동을 한 장으로 보여 주는 사진: 현장 전경, 발표 장면, 결과물. 로고 · 포스터는 사진이 없을 때만.
  - 표지가 없어도 됩니다. 없으면 제목 블록이 한 칸으로 나옵니다. 억지로 채우지 않습니다.
- **사진 줄(`shots`)**: 2–8장. 표지로 쓴 사진을 다시 넣어도 됩니다(표지에서는 잘려 보이므로).
  - [신규] 순서는 **시간순 또는 본문의 순서**. 첫 장이 가장 먼저 보이므로 활동을 잘 설명하는 사진을 앞에 둡니다.
  - 목록에서는 4:3 으로 가운데가 보입니다. 중요한 것이 가장자리에 있으면 미리 잘라서 넣습니다.
  - 사진마다 설명 글은 붙지 않습니다. 설명이 필요한 사진은 본문에서 글로 풉니다.
- 사진 줄 제목은 기본 '현장 사진'. 현장 사진이 아니면 `photosTitle` 로 바꿉니다(예: '교내 기사 화면 캡처').

### 8.3 영상 — 두 가지 방식

| | 직접 올린 영상 | 바깥 영상 |
| --- | --- | --- |
| 설정 | `common.js` `photos[id].video = {src:"video/이름.mp4", poster:"접두어_video_poster"}` + `ko/en.js` `vid` | `common.js` `activities` 의 `video:"https://www.youtube.com/…"` |
| 화면 | 사진 줄 아래 **영상 구역**(포스터 + 재생 버튼 + 설명). 프로젝트 카드에서는 마우스를 올리면 미리보기 | 상세 제목 아래 **'활동 영상' 버튼**(새 탭) |
| 언제 | 내가 만들었거나 프로젝트를 설명하는 90초 이하 영상 | 주최 측이 올린 영상, 긴 영상, 40MB 를 넘는 영상 |

- [신규] 영상은 저장소 용량을 크게 늘립니다(지금 3개 92MB). 새 영상은 **40MB 이하 · 720p** 로 줄여서 올리고, 그보다 크면 YouTube 에 올려 바깥 영상 방식으로 겁니다.
- 포스터는 영상의 대표 장면 한 컷입니다. 없으면 재생 전 화면이 검게 보입니다.
- 유형 A 는 포스터가 프로젝트 카드의 얼굴이 됩니다. 프로젝트 이름이나 화면이 보이는 컷을 고릅니다.

### 8.4 발표자료

```js
// common.js
decks: { line4: {file:"line4_slide_", count:15} }
```

- 슬라이드를 한 장씩 `.webp` 로 내보내 `접두어_slide_01` … 로 넣고, `count` 에 장 수를 적습니다.
- `ko.js` / `en.js` 의 `deck` 에 장(챕터)과 슬라이드 설명을 씁니다(5.7). 설명의 개수는 `count` 와 같아야 합니다.
- [신규] 20장 이하로 고릅니다. 표지 · 감사 인사 · 빈 장은 뺍니다.
- 발표자료가 있으면 본문에 같은 내용을 다시 길게 쓰지 않습니다. 본문에는 **자료에 없는 것**(왜 그렇게 했는지, 내 역할, 결과)을 씁니다.

### 8.5 바깥 링크

- 프로젝트 저장소 · 서비스 주소 · 이어지는 다른 활동: `panel.links` / `proj.links` (요약 패널의 버튼).
- 본문에서 언급한 자료 · 기사: 본문 `{link}`.
- [확인] 주소는 `https://` 로 시작합니다. 바깥 링크는 새 탭으로 열리고, `#a/id` 는 같은 탭에서 열립니다.
- [신규] 링크 글자는 **어디로 가는지**를 씁니다: `GitHub · Front-end`, `[HACKAFAIR 2024] Closing 영상`, `이어진 해외봉사 보기`. `여기`, `링크`, 주소 그대로 ✕.
- [신규] 로그인이 필요하거나 곧 사라질 주소(행사 임시 페이지, 개인 드라이브 공유 링크)는 걸지 않습니다.

| 대상 | 규칙 | 표기 |

## 9. 한국어와 영어

- [확인] **두 파일은 같은 모양**입니다. `ko.js` 에 있는 키는 `en.js` 에도 있어야 하고, `body` 의 블록 종류와 순서가 같아야 합니다(검증 스크립트가 비교합니다).
- [확인] 영어가 없을 때 화면에 일어나는 일:

  | 항목 | 영어가 비어 있으면 |
  | --- | --- |
  | `title` · `org` · `proj` · `panel` · `card` · `vid` · `deck` | 한국어가 대신 나옵니다 |
  | `summary` · `short` | **빈칸**으로 나옵니다 |
  | `body` | **본문이 통째로 비어** 나옵니다 |

  따라서 영어는 '나중에' 채우는 것이 아니라 **같은 커밋에서 함께** 씁니다.
- [신규] 번역은 문장 대 문장이 아니라 **블록 대 블록**으로 맞춥니다. 같은 사실 · 같은 숫자 · 같은 순서이면 되고, 표현은 영어답게 고칩니다.
- [신규] 두 언어의 `summary` 는 같은 내용을 담습니다. 한쪽에만 배경 설명을 길게 넣지 않습니다(영어가 한국어의 2.5배를 넘으면 다시 봅니다).
- [확인] 고유 이름은 공식 영문 표기를 씁니다(`FreeMed`, `KT&G Sangsang Withus`). 공식 표기가 없으면 로마자로 적고 처음 한 번 뜻을 풀어 씁니다(`jjokbang district`).
- [확인] 프로젝트 이름은 두 언어에서 같게 씁니다. 영어 이름을 따로 지었다면 `proj.name` 과 `title` 을 모두 맞춥니다.
- [확인] 영어는 한국어보다 1.5–2배 깁니다. 칩 · 버튼 · 목차 이름처럼 좁은 자리는 영어 화면에서 넘치지 않는지 확인합니다.
- 메뉴 · 버튼 · 라벨 글자는 `page` · `ui` 에 있습니다. 새 글자가 필요하면 두 파일에 같은 키로 넣습니다.

## 10. 메인 화면에 내보내기

새 활동은 추가하는 것만으로 **활동 기록 목록과 개수에 자동으로** 들어갑니다. 아래는 더 앞에 내세울 때만 고칩니다.

| 자리 | `common.js` | 개수 | 조건 | 같이 고칠 것 |
| --- | --- | --- | --- | --- |
| 프로젝트 카드 | `projects` | 지금 2개. 늘릴 수 있음 | 유형 A (`proj` + 영상 또는 포스터) | 순서대로 좌우가 번갈아 나옵니다 |
| 대표 활동 카드 | `featured` | **4개 고정** | `card` + 표지 사진 | `ko/en.js` `page.work.featuredSub` (네 활동을 한 줄로 요약한 글) |
| 활동 기록의 대표 카드 | `archiveReps` | **구분마다 1개** | `projects` · `featured` 와 겹치지 않을 것 | — |

- [확인] `featured` 는 4개로 설계되어 있습니다(넓은 화면 2×2, 휴대폰 2×2). 하나를 넣으면 하나를 뺍니다.
- [신규] 새 활동을 대표로 올릴지는 작성자가 정합니다. **요청이 없으면 `projects` · `featured` · `archiveReps` 를 바꾸지 않습니다.**
