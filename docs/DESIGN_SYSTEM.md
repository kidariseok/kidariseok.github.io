# Design System

JINSEOK OH 포트폴리오의 시각 규칙을 **코드에 구현된 값 그대로** 옮겨 적은 문서입니다.
새로운 디자인을 제안하는 문서가 아니라, 이미 있는 설계를 다시 만들 수 있게 하는 기준서입니다.

- 값의 원본은 항상 `index.html` 의 `<style>` 입니다. 이 문서와 코드가 다르면 **코드가 맞고**, 문서를 고칩니다.
- 줄 번호는 이 문서를 쓴 시점 기준입니다. 줄이 밀렸으면 선택자 이름(`.pstrip` 등)으로 찾으세요.
- 글 쓰는 규칙은 [CONTENT_GUIDELINES.md](CONTENT_GUIDELINES.md), 활동을 추가하는 순서는 [NEW_ACTIVITY_CHECKLIST.md](NEW_ACTIVITY_CHECKLIST.md), 지금 코드가 이 규칙에서 벗어난 곳은 [PORTFOLIO_AUDIT.md](PORTFOLIO_AUDIT.md)에 있습니다.

## 규칙 표기

| 표기 | 뜻 |
| --- | --- |
| **[확인]** | 지금 코드에 구현되어 있고 모든 화면이 따르는 규칙. 그대로 지킵니다. |
| **[신규]** | 코드에는 암묵적으로만 있던 것을 이번에 규칙으로 정한 것. 코드를 바꾸지 않아도 지킬 수 있습니다. |
| **[예외]** | 규칙에서 벗어나도 되는 경우. 적힌 조건 안에서만 허용합니다. |
| **[제안]** | 코드를 바꿔야 적용되는 개선안. 아직 적용하지 않았고, 승인 후에 진행합니다. |

## 1. 디자인 철학과 정체성

한 문장으로: **흰 바탕 위에 검은 카드, 그리고 파란색 한 가지.**

| 원칙 | 구체적으로 | 표기 |
| --- | --- | --- |
| 색은 세 가지 역할만 | 바탕(흰색 · 옅은 회색) · 검은 카드 · 파란 포인트. 네 번째 색을 장식으로 쓰지 않습니다. | [확인] |
| 파란색은 '눌러 볼 것'과 '핵심 숫자'에만 | 버튼, 링크, 작은 라벨(kicker), 요약 패널의 큰 숫자, 지금 선택된 항목. 본문 문장을 파랗게 칠하지 않습니다. | [확인] |
| 검은 카드는 '대표로 내세우는 것'에만 | 프로젝트 카드, 대표 활동 카드, 연락처, 이전/다음 활동, 봉사 합계. 일반 정보는 옅은 회색(`--soft`) 상자. | [확인] |
| 유리 효과는 '떠 있는 층'에만 | 상단 메뉴, 좁은 화면의 목차 띠, 사진 크게 보기의 버튼, 대화상자 뒷배경. 카드에는 쓰지 않습니다. | [확인] |
| 숫자는 맥락과 함께 한 번 | 첫 화면에 숫자 상자를 늘어놓지 않습니다. 숫자는 그 숫자가 나온 활동의 요약 패널이나 '이력'에서 한 번 보여 줍니다. | [확인] |
| 모든 상세 페이지는 같은 뼈대 | 활동 종류가 달라도 순서와 간격이 같습니다(4.9). 달라지는 것은 '있는 블록 / 없는 블록'뿐입니다. | [확인] |
| 장식보다 정보 | 움직임이 있는 장식은 첫 화면 배경 하나뿐입니다. 상세 페이지에는 장식용 그림 · 아이콘 · 그라디언트를 넣지 않습니다. | [확인] |
| 글자는 굵기로 위계를 만든다 | 색을 늘리는 대신 굵기(800 / 700 / 400)와 크기로 구분합니다. 기울임(italic)은 쓰지 않습니다. | [확인] |

**하지 않는 것** [신규]

- 새 색을 추가하지 않습니다. 필요한 색은 2.1의 토큰에서 고릅니다.
- 그림자를 새로 만들지 않습니다. `--shadow` 하나와 2.5에 적힌 예외만 씁니다.
- 활동 하나를 위해 CSS 클래스나 레이아웃을 새로 만들지 않습니다. 본문은 [CONTENT_GUIDELINES.md 6장](CONTENT_GUIDELINES.md#6-본문-블록-사전)의 블록 19종으로만 구성합니다.
- 이모지, 외부 아이콘 글꼴, 이미지로 된 글자를 쓰지 않습니다. 아이콘은 `index.html` 의 `<symbol id="ic-…">` 만 씁니다.
- 프레임워크 · 빌드 도구 · CSS 라이브러리를 들이지 않습니다. 순수 HTML / CSS / JavaScript 한 파일 구조를 유지합니다.

**쓰는 규칙**

1. [확인] 색은 반드시 `var(--토큰)` 으로 씁니다. 화면 위에 놓이는 요소에 `#hex` 를 직접 쓰면 어두운 화면에서 깨집니다.
2. [확인] 흰 바탕의 파란 글자는 `--accent-text`, 검은 카드의 파란 글자는 `--accent-2`, 채운 면은 `--accent`. 세 가지를 섞어 쓰지 않습니다.
3. [확인] 본문 글자는 `--text`, 제목과 굵은 글자는 `--ink`, 보조 글자는 `--muted`. 본문보다 옅은 글자를 만들려고 `opacity` 를 쓰지 않습니다 (예외: 5.2의 '선택되지 않은 것 흐리게').
4. [확인] 구분 색(`--ax`)은 상세 본문 안에서 쓰지 않습니다.
5. [예외] `#fff` 를 직접 쓰는 곳: 항상 어두운 면 위의 글자 (검은 카드 제목, `--accent` 로 채운 버튼의 글자, 첫 화면, 사진 위 버튼). 새로 쓸 때도 이 경우에만 허용합니다.
6. [예외] 숫자 비교 블록의 강조색은 `--warn` 토큰입니다(`#ff6a3d`. `.body .stat b.hi`). 팔레트 밖의 유일한 색이며 '기대와 다른 숫자' 하나를 짚을 때만 씁니다. 새로운 곳에 쓰지 않습니다. (밝은 화면이 `main` 에서 제거되어 어두운 값 하나만 있습니다.)

### 2.2 글꼴

| 토큰 | 값 | 쓰는 곳 |
| --- | --- | --- |
| `--sans` | `"Noto Sans KR","Apple SD Gothic Neo","Malgun Gothic",system-ui,sans-serif` | 본문, 한글 제목, 버튼. 기본 글꼴 |
| `--display` | `"Archivo","Noto Sans KR",system-ui,sans-serif` | 영문 대문자 라벨(kicker), 숫자, 로고, 프로젝트 이름, 카운터 |

- [확인] 불러오는 글꼴은 **Archivo**(가변 폭 62–125 · 굵기 500–900)와 **Noto Sans KR**(400 · 500 · 700 · 900) 두 가지뿐입니다 (`index.html` 28행).
- [확인] 굵기는 400(본문) · 500(메뉴) · 600(보조 강조) · 700(라벨 · 버튼) · 800(제목) · 900(첫 화면 이름과 핵심 문장)만 씁니다. Noto Sans KR 에는 800 파일이 없어 한글 800은 900으로 그려집니다 — 의도된 결과이니 700으로 낮추지 않습니다.
- [확인] 숫자가 세로로 정렬되어야 하는 곳에는 `.num`(`font-variant-numeric:tabular-nums`)을 붙입니다.
- [확인] 한글 줄바꿈은 `word-break:keep-all` (단어 중간에서 끊지 않음). 제목은 `text-wrap:balance`.

## 3. 어두운 화면 (Dark Mode)

- [확인] 기기 설정(`prefers-color-scheme: dark`)을 자동으로 따릅니다. 사이트 안에 전환 버튼은 없습니다.
- [확인] 어두운 화면에서 바뀌는 것은 **토큰 값뿐**입니다. 컴포넌트별로 어두운 화면용 규칙을 따로 쓰지 않습니다. 그래서 2.1의 규칙 1을 지키면 어두운 화면은 저절로 맞습니다.
- [확인] 토큰을 고칠 때는 **세 곳을 같이** 고칩니다: `:root`(48행), `@media (prefers-color-scheme: dark)`(73행), `:root[data-theme="dark"]`(83행). 구분 색은 436–441행.
- [확인] 검은 카드는 어두운 화면에서 한 단계 밝아지고(`--block` `#0a0c10` → `#161a22`) 얇은 테두리(`--block-line`)가 생겨 바탕과 구분됩니다.
- [확인] 첫 화면과 맨 아래 띠는 두 화면 모두 검은색입니다.
- [신규] 사진 · 슬라이드 · 영상은 색을 바꾸지 않습니다. 흰 바탕의 문서 이미지(이수증, 기사 캡처)도 그대로 둡니다.
- [신규] 새 요소를 만들면 밝은 화면과 어두운 화면에서 **둘 다** 확인합니다 ([NEW_ACTIVITY_CHECKLIST.md](NEW_ACTIVITY_CHECKLIST.md) 5단계).

### 4.13 목차 (`.toc`, 595–612행 · `buildToc`)

- **본문 소제목(`{h}`)이 3개 이상이면 자동으로** 생깁니다. 직접 켜고 끄지 않습니다.

- 항목 이름은 `tocLabel()` 이 정합니다: `toc` 값 → 없으면 `k`("01 · 문제" → "01 문제") → 없으면 "01. 상황: …" 에서 "01 상황" → 없으면 소제목 전체.

## 5. 인터랙션

### 5.1 마우스를 올렸을 때 (hover)

| 대상 | 반응 |
| --- | --- |
| 큰 카드 (프로젝트 · 대표 활동) | 4px 위로 + `--shadow`, 안의 '보기 →' 가 `--accent-2`, 화살표 3px 오른쪽 |
| 중간 카드 (사진, 활동 기록 대표, 이전/다음, 이수증) | 3px 위로 + `--shadow` (이전/다음은 그림자 대신 바탕이 `--accent`) |
| 글자 링크 | 색이 진해지거나(`--muted` → `--ink`) 밑줄 |
| 선 버튼 · 알약 | 색 반전 또는 테두리가 `--ink` 로 |
| 오른쪽 화살표가 있는 것 | 화살표만 3px 오른쪽 (내려받기 화살표는 2px 아래) |

- [확인] 떠오르는 높이는 큰 카드 4px, 중간 카드 3px, 버튼 2px 세 가지뿐입니다.
- [확인] hover 로만 보이는 정보는 없습니다. 터치 기기에서도 같은 내용이 보입니다 (프로젝트 영상 미리보기는 장식이며 상세 페이지에서 볼 수 있습니다).

### 5.2 선택 · 진행 상태

- 지금 선택된 항목: `--ink` 채움(알약) 또는 `--accent-text` + 파란 선(세로 목차). 상태는 `aria-pressed` / `aria-current` 로도 알립니다.
- 선택되지 않은 것을 흐리게 하는 곳은 두 군데뿐: 소개 단계(`opacity:.5`), 슬라이드 미리보기(`opacity:.5`).

### 5.3 스크롤

- 페이지 안 이동은 부드럽게(`scroll-behavior:smooth`). 고정된 메뉴에 가리지 않도록 `scroll-padding-top` 80px (980px 이하 메인 화면 118px).
- 가로로 넘기는 영역: 사진 줄(스냅), 장 칩, 좁은 화면의 메뉴 · 목차 띠, 봉사 표. 이 영역 밖에서는 가로 스크롤이 생기면 안 됩니다.
- 첫 화면: 1.4화면 동안 붙잡혀 있으면서 스크롤에 맞춰 글자가 사라지고 → 배경이 흐려지고 → 화면이 흰색으로 밝아지고 → 큰 이름이 메뉴 로고 자리로 이동합니다. 시간이 아니라 스크롤 위치로 계산하므로 올리면 그대로 되감깁니다 (두 번째 `<script>`).

### 5.4 페이지 이동

- 주소는 `#a/활동id` 입니다 (예: `#a/freemed`). 파일은 `index.html` 하나이고, 목록 화면(`#list-view`)과 상세 화면(`#detail-view`)을 바꿔 보여 줍니다 (`route()`).
- 상세로 들어가면 맨 위로 이동합니다. 목록으로 돌아오면 **들어가기 전 스크롤 위치로** 돌아옵니다(`listScroll`).
- 뒤로 가기 링크는 들어온 섹션으로 갑니다(SELECTED WORK → `#work`, 활동 기록 → `#activities`). 주소로 바로 들어온 경우 SELECTED WORK 에 있는 활동이면 `#work`, 아니면 `#activities`.
- 언어를 바꾸면 지금 보던 화면이 그 자리에서 다시 그려집니다. 선택한 언어는 `localStorage` 의 `jso-lang` 에 저장됩니다.
- 활동 id 를 바꾸면 예전 주소가 끊어집니다. 바꿔야 한다면 `LEGACY_IDS` 에 옛 이름을 등록합니다.

## 6. 접근성

### 6.1 지켜지고 있는 것 [확인]

- 초점 표시: 전역 `:focus-visible{outline:2.5px solid var(--accent-2);outline-offset:3px;border-radius:8px}` (103행). 없애지 않습니다.
- 키보드: 모든 버튼 · 링크에 Tab 으로 갈 수 있고, 발표자료는 ← →, 크게 보기 · 창은 Esc 로 닫힙니다. 메뉴는 Tab 으로 들어오면 내려옵니다.
- 제목 순서: 메인은 `h1`(이름) → `h2`(섹션) → `h3`(묶음 · 카드), 상세는 `h1`(활동 제목) → `h2`(구역 · 본문 소제목) → `h3`.
- 언어: `<html lang>` 이 KO / EN 에 따라 바뀝니다.
- 상태 알림: 언어 버튼 `aria-pressed`, 목차 `aria-current`, 펼침 버튼 `aria-expanded`, 슬라이드 설명 `aria-live="polite"`.
- 장식 요소(배경 canvas, 아이콘, 카드의 표지 사진)는 `aria-hidden` 또는 빈 `alt`.
- 크게 보기와 봉사 내역 창은 `role="dialog"` · `aria-modal`, 닫으면 초점이 연 버튼으로 돌아갑니다.
- '동작 줄이기' · '투명도 줄이기' 설정을 따릅니다.
- 가로 스크롤 없음: 20개 상세 페이지 × 3개 화면 폭 × 2개 언어에서 넘치는 요소 0건.

### 6.2 새로 만들 때의 규칙 [신규]

1. 누를 수 있는 것은 `<a>`(이동) 또는 `<button type="button">`(동작)으로 만듭니다. `<div>` 에 클릭을 붙이지 않습니다.
2. 글자가 없는 버튼(아이콘만, 사진만)에는 `aria-label` 을 붙입니다. 글자는 `ko.js` / `en.js` 의 `ui` 에서 가져옵니다.
3. 내용을 전달하는 이미지(이수증, 기사 캡처)에는 `alt` 를 씁니다. 분위기를 보여 주는 현장 사진은 빈 `alt` + 버튼의 `aria-label`.
4. 색만으로 뜻을 전하지 않습니다. 선택 상태에는 굵기나 채움이 함께 바뀌고, 구분에는 이름과 아이콘이 함께 나옵니다.
5. 글자 대비는 2.1의 조합만 씁니다. `--line` 과 `--muted` 를 옅은 바탕 위 작은 글자에 겹쳐 쓰지 않습니다.
6. 새 텍스트를 넣으면 한국어와 영어 모두에서 줄바꿈과 넘침을 확인합니다. 영어가 보통 1.5–2배 깁니다.

### 6.3 알려진 한계

터치 기기(`pointer:coarse`)에서는 버튼 · 링크 주변에 보이지 않는 44px 높이의 터치 영역을 둡니다(`::after`). 크게 보기는 열려 있는 동안 Tab 초점을 안에 가두고 뒤 페이지 스크롤을 막습니다(`html.modal-open`). 알려진 한계: 작은 라벨 · 알약 버튼의 변형이 많음([AUDIT A-02 · A-03](PORTFOLIO_AUDIT.md), 승인 대기).
