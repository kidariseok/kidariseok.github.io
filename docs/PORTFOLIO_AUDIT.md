# Portfolio Audit

포트폴리오의 디자인 · 콘텐츠 · 구현을 전수 검토한 결과입니다. 규칙 자체는 [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md)와 [CONTENT_GUIDELINES.md](CONTENT_GUIDELINES.md)에 있고, 이 문서는 **지금 상태가 그 규칙과 어디서 다른지**와 **무엇을 먼저 고칠지**를 적습니다.

- 검토 시점: 2026-11-12, `main` 의 `1b8f2e5` 기준
- 줄 번호는 이 문서와 함께 커밋된 파일 기준입니다.

## 2. 종합 평가

**시각 시스템은 이미 일관됩니다. 일관되지 않은 것은 '글의 구조'였습니다.**

모든 상세 페이지가 하나의 함수(`renderDetail`)로 그려지기 때문에, 20개 페이지 × 3개 폭에서 구역 순서와 간격이 **1px 오차 안에서 전부 같았습니다**(뒤로 → 상단 28 → 요약 패널 24 → 사진 40 / 16 → 영상 · 발표자료 48 → 본문 → 이전/다음 36). 가로로 넘치는 요소도 0건입니다. 페이지마다 달라 보였던 원인은 CSS 가 아니라 **콘텐츠 파일에 무엇을 어떤 형식으로 넣느냐가 정해져 있지 않았던 것**입니다: 소제목 번호를 붙이는 방식이 네 가지, 요약 패널이 6칸인 페이지와 1칸인 페이지, 한국어 페이지 안의 영어 작은 제목 등.

## 3. 지금의 구조 (요약)

```
index.html          화면 구조 · 스타일 · 동작 전부 (빌드 없음)
  <style>           [1] 색 · 글꼴 토큰 → 컴포넌트 → 화면 폭별 규칙
  <body>            [2] 메인 화면의 고정 틀 (글자는 data-t 로 채움) + 빈 상세 화면
  <script> 1        [3] content 세 파일을 합쳐 목록 · 상세를 그림, 주소(#a/id) 처리, 언어 전환
  <script> 2        첫 화면 전환 (숨은 메뉴 + 스크롤에 따른 초점 이동)
  <script> 3        첫 화면 배경 (WebGL)
content/common.js   언어와 무관한 값: 활동 id · 날짜 · 구분, 사진, 발표자료, 메인 노출, 이력
content/ko.js       한국어 글자
content/en.js       영어 글자 (ko.js 와 같은 모양)
img/ video/ cv/     사진 · 슬라이드(.webp), 영상(.mp4), CV(.pdf)
docs/               규정 문서 (이번에 추가)
tools/              검증 스크립트 (이번에 추가)
```

**잘 되어 있어 그대로 지켜야 하는 것**

1. 내용과 구조의 분리 — 활동을 추가할 때 `index.html` 을 건드리지 않아도 됩니다.
2. 상세 페이지의 단일 렌더러 — 새 페이지가 기존 페이지와 달라질 구조적 여지가 없습니다.
3. 본문 블록 방식 — 자유로운 HTML 대신 정해진 블록만 쓰므로 모양이 흐트러지지 않습니다.
4. 팀의 일과 내 일을 색으로 구분하는 약속(`--accent-soft` + 파란 테두리 = 내가 한 것).
5. 날짜를 요약 패널 한 곳에만, 숫자를 맥락과 함께 한 번만 보여 주는 원칙.
6. 설정 존중 — 어두운 화면, 동작 줄이기, 투명도 줄이기.
7. 코드 주석이 한국어로 '어디를 고치면 되는지'를 설명하고 있습니다.

문서에서 **[확인]** 으로 표시한 것은 코드와 기존 페이지에 이미 있던 규칙이고, **[신규]** 는 이번에 정한 것입니다. 새로 정한 것만 모으면 다음과 같습니다.
