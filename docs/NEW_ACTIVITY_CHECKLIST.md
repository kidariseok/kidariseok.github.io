# New Activity Checklist

새 활동 · 프로젝트 하나를 사이트에 올리는 **전체 순서**입니다. 위에서 아래로 따라 하면 기존 페이지와 같은 모양의 페이지가 나옵니다.

- 무엇을 어떻게 쓰는지: [CONTENT_GUIDELINES.md](CONTENT_GUIDELINES.md)
- 화면이 어떻게 생겼는지: [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md)

> **원칙 한 줄**: 새 활동은 `content/` 세 파일과 `img/` 에 **데이터를 더하는 일**입니다. `index.html` 의 CSS · HTML · JavaScript 는 고치지 않습니다.

## 한눈에 보기

```
0. 정보 모으기      → 1. 유형 · 구분 정하기 → 2. 사진 · 영상 준비
3. common.js 등록   → 4. ko.js · en.js 작성 → 5. 화면 확인
6. 버전 올리고 커밋
```

| 고치는 파일 | 항상 | 필요할 때만 |
| --- | --- | --- |
| `content/common.js` | `activities` 에 한 줄 | `photos` · `decks` · `projects` · `featured` · `archiveReps` · `volunteerLog` |
| `content/ko.js` | `activities[id]` | `page.work.featuredSub`(대표 활동을 바꿨을 때) · `volunteerLog` 이름 |
| `content/en.js` | `activities[id]` (ko.js 와 같은 모양) | 위와 같음 |
| `img/` · `video/` | — | 표지 · 사진 · 슬라이드 · 포스터 · 영상 |
| `index.html` | 맨 아래 `?v=숫자` 세 곳 | **그 밖에는 고치지 않습니다** |
| `README.md` | — | 'What's inside' 의 개수 |

## 0. 정보 모으기

아래 표를 채웁니다. **●** 는 없으면 페이지를 만들 수 없는 것, ○ 는 있으면 좋은 것입니다.

| | 항목 | 어디에 쓰이나 | 예 |
| --- | --- | --- | --- |
| ● | 활동의 공식 이름 (한 · 영) | `title` | KT&G 상상위더스 해외봉사단 |
| ● | 시작일 (끝난 날) | `start` · `end` | 2024-10-29 ~ 2025-02-28 |
| ● | 내가 맡은 직책과 한 일 | `panel.role`, 본문 | 회계·물품팀 · 양치질 교육 기획 및 주진행 |
| ● | 무엇을 했는지 2–3문장 | `summary`, 본문 도입 | |
| ○ | 주최 기관 · 장소 | `panel.where` | 인도네시아 보고르 · 바바칸마당 초등학교 |
| ○ | 팀 인원과 구성 | `panel.team` | 해외봉사단 40명 (4개 조) |
| ○ | 규모 (참가자 · 횟수 · 시간) | `panel.scale` | 참가자 50명 · 9개 팀 |
| ○ | 결과와 그 근거 | `panel.result` · `key` | 봉사 177시간 (1365 확인서) |
| ○ | 과정에서의 장면 · 판단 · 배운 점 | 본문 | 메모, 회고, 보고서 |
| ○ | 사진 (표지 1 + 현장 2–8) | `photos` | |
| ○ | 발표자료 (PDF · 이미지) | `decks` + `deck` | |
| ○ | 영상 파일 또는 주소 | `photos.video` 또는 `video` | |
| ○ | 링크 (저장소 · 기사 · 서비스) | `links` · `{link}` | |
| ○ | 프로젝트라면: 종류 · 기술 · 내가 쓴 도구 | `proj` | AI · 웹 서비스 / React, Spring Boot / Figma |

### 정보가 부족할 때의 기본 결정

추가로 묻지 않고 진행해도 되는 것과, 반드시 확인해야 하는 것을 나눕니다.

| 상황 | 기본 결정 |
| --- | --- |
| 구분(category)을 말해 주지 않았다 | [CONTENT_GUIDELINES 3장](CONTENT_GUIDELINES.md#3-활동-구분-category)의 기준 '내가 주로 한 일'로 정하고, 보고할 때 어떤 구분으로 넣었는지 알립니다 |
| 유형(A · B · C)을 말해 주지 않았다 | 받은 자료의 양으로 정합니다. 장면 · 회고가 4개 이상의 주제로 나뉘면 B, 결과물과 기술 스택이 있고 내가 기획 · 제작했으면 A, 그 밖은 C |
| 영어 내용이 없다 | 한국어를 바탕으로 **영어도 함께 씁니다**(비워 두면 영어 화면의 본문이 빕니다). 고유 이름의 영문 표기를 확인할 수 없으면 보고에 적습니다 |
| 사진이 없다 | 표지 · 사진 줄 없이 만듭니다. 임의의 그림 · 스톡 사진 · 생성 이미지를 넣지 않습니다 |
| 사진이 세로형뿐이다 | 표지로는 가장 가로에 가까운 것을 고르거나 표지를 비우고 사진 줄에만 넣습니다 |
| 메인 화면에 올릴지 말이 없다 | `projects` · `featured` · `archiveReps` 를 **바꾸지 않습니다.** 활동 기록 목록에는 자동으로 들어갑니다 |
| 날짜가 '2024년 봄' 정도로만 있다 | 임의의 날짜를 만들지 않습니다. 정렬에 쓸 가장 이른 날짜를 넣고 `noDate:true` 로 화면에서 숨긴 뒤 보고합니다 |
| 숫자 · 사실이 확인되지 않는다 | 그 칸을 비우거나 `[확인 필요] …` 로 적고(화면에 점선으로 표시됨) 보고에 목록으로 남깁니다. **지어내지 않습니다** |
| 사진에 다른 사람의 얼굴 · 주소가 있다 | 올리지 않고 먼저 알립니다. 흐림 처리된 파일을 받아서 진행합니다 |
| 기존 블록으로 표현할 수 없는 내용이 있다 | 가장 가까운 블록으로 풀고, 새 블록이 필요하다고 판단되면 만들지 말고 제안합니다 ([DESIGN_SYSTEM 7장](DESIGN_SYSTEM.md#7-규칙을-넓혀야-할-때)) |

## 1. 유형과 구분 정하기

- [ ] **id** 를 정했다 — 영문 소문자 · 숫자 · 하이픈, 기존 id 와 겹치지 않음. 공개 후에는 바꾸지 않습니다.
- [ ] **구분**을 정했다 — `project` / `community` / `edu` / `learn` ([기준](CONTENT_GUIDELINES.md#3-활동-구분-category)).
- [ ] **유형**을 정했다 — A 프로젝트 / B 기록 / C 간단 기록 ([기준](CONTENT_GUIDELINES.md#4-페이지-유형)).
- [ ] **가장 비슷한 기존 페이지**를 하나 골라 `ko.js` 에서 열어 두었다.

| 내가 쓰려는 것 | 본보기로 볼 기존 활동 (id) |
| --- | --- |
| 유형 A · 영상과 발표자료가 있는 프로젝트 | `line4` |
| 유형 A · 영상만 있는 프로젝트 | `goormthon` |
| 유형 B · 행사 · 동아리 운영 | `realthon`, `gdsc` |
| 유형 B · 봉사 · 교육 (사진 많음) | `freemed`, `ktng-overseas` |
| 유형 B · 강연 · 박람회 · 수업 정리 | `edutech-expo`, `intl-publication` |
| 유형 B · 발표자료가 중심인 공모전 · 캠프 | `trade-ai`, `ba-dive` |
| 유형 B · 이수증이 있는 과정 | `future-tech` |
| 유형 C · 짧은 기록 | `audivice`, `worldvision` |

## 2. 사진 · 영상 준비

규격 전체는 [CONTENT_GUIDELINES 8장](CONTENT_GUIDELINES.md#8-사진--영상--발표자료).

- [ ] 개인정보를 확인했다 — 다른 사람의 얼굴, 주소 · 문패 · 번호판, 문서의 번호 · 서명 ([8.6](CONTENT_GUIDELINES.md#86-개인정보-보호)).
- [ ] 모두 `.webp` 로 바꿨다. 긴 변 1400px, 한 장 250KB 이하.
- [ ] 이름을 규칙대로 붙였다 — `접두어_cover` · `접두어_01` · `접두어_slide_01` · `접두어_video_poster`.
- [ ] 표지는 가로형(16:9 – 3:2)이다.
- [ ] 슬라이드는 16:9 이고 01 부터 빠짐없이 이어진다.
- [ ] 영상은 40MB 이하 · 720p 이고, 포스터(1280×720)가 있다. 더 크면 YouTube 주소로 건다.

변환 명령 (도구가 설치되어 있을 때):

```bash
# 사진 → webp (긴 변 1400px, 품질 80, 위치 정보 제거)
cwebp -q 80 -resize 1400 0 -metadata none 원본.jpg -o img/접두어_01.webp
```

```bash
# 세로 사진은 높이를 1400px 로
cwebp -q 80 -resize 0 1400 -metadata none 원본.jpg -o img/접두어_02.webp
```

```bash
# 발표자료 PDF → 슬라이드 이미지 (1440×810 기준)
pdftoppm -png -scale-to-x 1440 -scale-to-y -1 발표자료.pdf /tmp/slide
```

```bash
# 위에서 나온 PNG 를 번호 순서대로 webp 로
n=1; for f in /tmp/slide-*.png; do cwebp -q 82 "$f" -o "img/접두어_slide_$(printf %02d $n).webp"; n=$((n+1)); done
```

```bash
# 영상 줄이기 (720p, H.264) 와 포스터 뽑기 (3초 지점)
ffmpeg -i 원본.mov -vf scale=-2:720 -c:v libx264 -crf 27 -preset slow -c:a aac -b:a 96k -movflags +faststart video/이름.mp4
```

```bash
ffmpeg -ss 3 -i video/이름.mp4 -frames:v 1 -vf scale=1280:720 /tmp/poster.png && cwebp -q 80 /tmp/poster.png -o img/접두어_video_poster.webp
```

## 3. `content/common.js` 등록

- [ ] `activities` 에 한 줄을 넣었다 — **`start` 가 늦은 것이 위**가 되는 자리에.

```js
{
  id: "새id",
  start: "2026-10-01",
  end: "2026-12-20",          // 하루짜리면 이 줄을 뺍니다
  category: "project",        // project / community / edu / learn
  notion: ""                  // 원본 기록 id (없으면 "")
},
```

- [ ] 사진이 있으면 `photos` 에 등록했다 (확장자 없이).

```js
"새id": {cover:"접두어_cover", shots:["접두어_01", "접두어_02", "접두어_03"]},
```

- [ ] 직접 올린 영상이 있으면 같은 항목에 `video` 를 넣었다.

```js
"새id": {
  cover: "접두어_cover",
  video: {src:"video/이름.mp4", poster:"접두어_video_poster"}
},
```

- [ ] 바깥 영상(YouTube)이면 `activities` 줄에 `video:"https://…"` 를 넣었다.
- [ ] 발표자료가 있으면 `decks` 에 등록했다.

```js
"새id": {file:"접두어_slide_", count:15},
```

- [ ] (요청받았을 때만) 메인 화면 노출을 바꿨다 — [CONTENT_GUIDELINES 10장](CONTENT_GUIDELINES.md#10-메인-화면에-내보내기). `featured` 를 바꿨다면 `ko/en.js` 의 `page.work.featuredSub` 도 고친다.
- [ ] 봉사 시간이 생겼으면 `volunteerLog.records` 에 줄을 더하고 `issued` 를 고쳤다.

## 7. 기존 활동을 고치거나 지울 때

- **글만 고칠 때**: `ko.js` 와 `en.js` 를 같이 고치고 5 · 6단계를 그대로 합니다.
- **사진을 바꿀 때**: 같은 이름으로 덮어쓰면 방문자에게 예전 사진이 한동안 보일 수 있습니다. **새 이름으로 올리고** `common.js` 를 고칩니다.
- **id 를 바꿀 때**: 세 파일의 id 를 모두 바꾸고, `index.html` 의 `LEGACY_IDS` 에 `옛id:"새id"` 를 넣어 예전 주소가 이어지게 합니다. 다른 활동의 `links` 에 있는 `#a/옛id` 도 찾아 고칩니다.
- **지울 때**: 세 파일의 항목, `photos` · `decks`, `projects` · `featured` · `archiveReps`, 다른 활동의 `#a/id` 링크, 쓰이지 않게 된 `img/` · `video/` 파일을 함께 지웁니다. 검사 스크립트가 끊어진 연결을 찾아 줍니다.

## 8. 하지 않는 것

- `index.html` 에 활동 하나만을 위한 CSS · HTML · JavaScript 를 더하지 않습니다.
- 새 색 · 새 글자 크기 · 새 블록 종류를 만들지 않습니다. 필요하면 제안합니다.
- 구분(category)을 늘리지 않습니다.
- 요청 없이 `projects` · `featured` · `archiveReps` 와 메인 화면 문구를 바꾸지 않습니다.
- 받지 않은 사실 · 숫자 · 인용 · 사진을 만들어 넣지 않습니다.
- `.png` · `.jpg` 를 `img/` 에 넣지 않습니다(`.webp` 만 불러옵니다).
- 한쪽 언어만 올리지 않습니다.
