## 2.1 10초 요약

**"AI 서비스 기획(PM) 경험이 두 번 있고, 대학 동아리 · 연합 행사 운영을 많이 해 본 컴퓨터교육과 학생이다."**

메모:
- 쓰는 데 문제는 없음. 다만 **프로젝트 카드 2장의 RESULT가 약함** — "6주 만에 서비스 배포", "부스를 열어 오프라인으로 운영". 둘 다 '했다'만 있고 '얼마나 / 어떻게 됐다'가 없음.
- 숫자는 오히려 아래 **대표 활동(운영 · 봉사) 카드에 몰려 있음** (50명 · 9개 팀, 300명, 220만 원, 34명, 177시간). 그래서 30초 안에는 '서비스 기획자'보다 **'행사 · 커뮤니티 운영 잘하는 사람'으로 먼저 읽힘.** 지원 직무가 AI · 서비스 기획이면 순서가 거꾸로 느껴짐.
- 카드 디자인은 깔끔하고, MY ROLE / RESULT 줄이 있어서 데스크톱에서 넘기기는 쉬움.

## 2.4 유지할 것

1. **데스크톱 메인 카드의 MY ROLE / RESULT 두 줄 구조** (`main_ko_desk_work2–3`). 대표 활동 4장이 같은 순서라 나란히 비교가 됨. 고칠 때 이 틀은 건드리지 말 것.
2. **RE:ALThon 요약 한 문장** — "일본 대학과의 글로벌 협업이 무산되자 방향을 바꿔, … 3개 대학 공동 AI 해커톤(50명 · 9개 팀)을 기획하고 개최함." 문제 → 판단 → 결과가 한 줄에 다 있음. 6개 중 유일. 다른 활동 요약의 본보기.
3. **line4 상세의 팀 구분** — TEAM "6인 팀 (기획·PM 1 · UI 디자인 1 · FE/BE 4)" + "STACK · 팀 개발". 본문의 "개발 코드는 직접 작성하지 않았습니다"도 신뢰에 큰 도움. 이 정직함을 메인까지 끌어올리는 게 S-01.
4. **분모가 붙은 숫자** — "설문 37명 중 35명", "3학년 1개 학급(34명)", "40명 (4개 조 · 조별 10명)". 숫자가 무엇의 숫자인지 바로 읽힘.
5. **RE:ALThon · GDG의 목차 "상황 → 판단 → 실행 → 결과"** (`realthon_ko_desk_2`). 스크롤 한 번에 이야기 구조가 보여서 끝까지 안 읽어도 됨.
