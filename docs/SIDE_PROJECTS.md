# Side Projects — 사이드 프로젝트 운영 원칙

메인 화면 `#side`(사이드 프로젝트) 영역을 **계속 이어 붙이기 위한 규칙**입니다. 새 프로젝트를 올리거나 상태 · 숫자를 바꿀 때 먼저 읽습니다.
저장소 공통 규칙(`CLAUDE.md`: 블록 19종, 한·영 동시, `/add-activity`, `check-content`)은 그대로 따르고, 이 문서는 사이드 프로젝트에만 더해지는 규칙입니다.

- 데이터 위치: `content/common.js` 의 `side`(카드 · 목록 · 로그 · 도구 · 통계 숫자), `content/ko.js`·`en.js` 의 `page.side`(문구). 대표 카드는 `activities` 의 활동 하나이며 상세 페이지는 `#a/id`.
- 화면: `index.html` 의 `renderSide()` 하나가 그립니다. 스타일은 `.sd-*` (색은 토큰만).
- 통계 갱신: `node tools/side-stats.mjs` (숫자만 출력, 기록 내용은 저장하지 않음) → 출력값을 `common.js` 의 `side.stats` 에 붙이고 `updated` 를 바꿉니다.

### 1. 단위와 이름
- 프로젝트 하나 = 활동 하나(`activities`의 id). 구분(category)은 `project`. 공개 뒤 id는 바꾸지 않는다.
- 여러 저장소를 묶은 것(예: Orca 봇 팀 + 공용 볼트)도 하나의 id로 둔다.

### 2. 세 단계와 올라가는 조건
| 단계 | 들어가는 조건 | 보여 주는 것 |
|---|---|---|
| 빌드 로그 | 시작했거나 의미 있는 사건(출시 · 전환 · 중단)이 있음 | 날짜 · 이름 · 한 줄 |
| 한 줄 목록 | 공개 링크 **또는** 실제 화면 1장 + 상태를 정할 수 있음 | 아이콘 · 이름 · 상태 배지 · 한 줄 |
| 대표 카드 + 상세 | 막힌 점과 해결을 **출처 있게** 쓸 수 있음 + 실제 화면 2장 이상 | 카드(WHY · ME vs AI · STUCK → FIX) + 상세 01~06·돌아보며 |
- 대표 카드는 최대 4개. 다섯 번째가 생기면 마지막 업데이트가 가장 오래된 카드가 한 줄 목록으로 내려간다(상세 페이지는 남김).
- 순서: 대표 카드는 상태(운영 중 → 출시 준비 → 실험 → 보류), 같은 상태 안에서는 최근 업데이트 순.

### 3. 상태 배지 정의 (4종, 새 상태를 만들지 않음)
| 상태 | 조건 |
|---|---|
| 운영 중 · 출시됨 | 지금 누구나 쓰거나 내려받을 수 있음 |
| 출시 준비 | 배포됐거나 출시일이 정해짐(체험판 공개 포함) |
| 실험 | 개인 도구 또는 검증 중, 외부 공개 계획 없음 |
| 보류 | 30일 넘게 작업 없음. **멈춘 이유 한 줄 필수** |
- 배지 옆 날짜는 '마지막 의미 있는 업데이트' 하나만.

### 4. 숫자 규칙
- 모든 숫자에 출처(파일 · 커밋 · 공개 페이지 · 볼트 노트)와 기준일을 남긴다(볼트 근거 노트 → 사이트 순서).
- AI 에이전트가 보고한 값은 **다시 실행해 확인한 뒤에만** 싣는다. 재현할 수 없으면 싣지 않는다(예: FIGHTSHOOT 글자 생성 584→82는 측정 스크립트가 없어 뺌, 2026-11-26).
- 운영 환경에 쓰기가 일어나는 측정(부하 점검 등)은 다시 돌리지 않고 '기록값 + 날짜'로 표기한다.
- 비공개 지표: SWIRLD 사용자 수, 블로그 조회수. 공개하기로 바꾸기 전에는 쓰지 않는다.

### 5. 활동 통계 정의
- 커밋: 계정의 공개·비공개 저장소 기본 브랜치 커밋 수, **AI 에이전트 커밋 포함**(문구로 밝힘). 기간은 첫 커밋(2026-09-23)부터.
- 잔디: 날짜별 커밋 수, 5단계(0 / 1–9 / 10–24 / 25–49 / 50+).
- AI 작업 시간: Claude Code · Codex 로컬 기록 타임스탬프, 15분 넘게 멈춘 구간 제외. 오래된 기록이 지워지므로 '최소값'으로 표기.
- 갱신: 월 1회(또는 새 대표 카드를 올릴 때) 스크립트로 다시 계산하고 기준일을 바꾼다. 사이트 반영 시 `tools/side-stats.mjs`로 만든다(숫자만 저장, 기록 내용은 저장하지 않음).

### 6. 역할 문구
- 기본 문장: "기획 · 결정 · 검수는 제가, 구현은 AI 에이전트가." 코드를 직접 썼다고 쓰지 않는다.
- 카드에는 ME vs AI 줄, 상세에는 05 'AI와 나의 분업'(AI가 한 일 / MY CONTRIBUTION)을 반드시 둔다.
- 'AI가 틀렸던 장면'이 있으면 우선해서 쓴다(신뢰 포인트). 예: 렉 수정이 아이폰 화면을 검게 만든 일.

### 7. 이미지
- 실제 운영 화면만: 스토어 스크린샷, 운영 사이트 캡처, 실제 게임 화면, 실제 앱 아이콘. 디자인 시안 · 무드보드 · 생성 이미지 단독은 쓰지 않는다.
- 사람 이름이 보이면 예시 이름인지 확인(예: endofyear 캡처의 '민지'는 캡처 문서상 예시). 확인 안 되면 쓰지 않는다. 얼굴 · 주소 · 문서 번호 금지.
- 캡처는 날짜를 남기고, 사이트 규격(webp · 긴 변 1400px · 250KB 이하, 이름 `접두어_shot_01`)으로 변환한다.

### 8. 써 본 AI 도구
- 도구마다 요금제 · 역할 · 실제 사용 장면 2~3개 · 쓰인 프로젝트. 장면은 볼트 근거가 있는 것만.
- 요금제가 바뀌면 날짜와 함께 갱신(예: Claude Pro → Max 2026-11-16).

### 9. 갱신 절차 (새 프로젝트 · 상태 변경 때)
1. 볼트에 근거 노트 작성 또는 갱신(사실 · 숫자 · 출처 · 미확인 구분).
2. 해당 단계 조건 확인 → 빌드 로그 / 목록 / 카드 중 어디에 넣을지 결정.
3. 숫자 재확인, 이미지 개인정보 확인.
4. 저장소 규칙대로 한·영 동시 작성, `node tools/check-content.mjs` 오류 0 · 새 경고 0.
5. PR로 올리고 미리보기에서 확인 후 병합.
