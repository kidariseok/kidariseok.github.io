## 1. Product Definition (Phase 1)

**한 줄:** 출근하는 길에 질문 하나를 지나고, 한 주를 모으면 궁금했던 동료에게 사내 카페 커피 한 잔을 건네는 사내 앱.

| 항목 | 정의 |
|---|---|
| Problem | 회사 사람에게 처음 말을 걸 작은 이유가 없다. 업무로만 연결된 사람들은 서로를 사람으로 알 기회가 거의 없고, 나이나 직급이 다르면 먼저 다가가기가 더 어렵다. 그 빈자리는 짐작으로 채워진다. (배경: 2024년 프로젝트의 세대 간 이해 부족) |
| Target User | 사내 카페가 있는 수십~수백 명 규모 회사의 구성원 전체. 모두가 보내는 사람이자 받는 사람이다. 나이나 직급에 따라 화면이 달라지지 않는다 |
| Core Value | 회사 사람들이 조금 궁금해지고, 말을 걸 작은 핑계가 생긴다 |
| Core Experience | 출근하려면 질문 하나에 답하고 다른 사람들의 답을 예상해야 한다. 출근이 완료되면 지난 질문의 결과가 열려 "생각과 다르네"를 발견한다. 한 주를 모으면 탑이 생기고, 탑으로 선물을 골라 누군가에게 건넨다. 받은 사람에게는 "왜 나한테?"라는 작은 사건이 생긴다 |
| Core Loop | 출근·퇴근 때마다: 등록 → 내 답 → 예상 → 완료, 조약돌 +1 → 지난 질문 결과. 가끔: 탑 → 스토어 → 건넴 → 받음, 짧은 화답 → (앱 밖, 선택) 사내 카페에서 한 잔 |
| Role of Pebble | 질문 하나 = 조약돌 하나. 10개 = 탑 하나 = 2,000원만큼. 탑은 스토어에서 선물을 고르는 단위 |
| Role of Questions | 출근과 퇴근의 관문. 정답이 없고 10초면 지난다. 하루 두 번 다른 사람을 떠올리게 하는 핑계 |
| Role of Guess | 다른 사람을 한 번 떠올리게 하는 장치. 예상이 있어야 결과가 "내 생각과의 비교"가 된다. 맞혀도 보상이 없다 |
| Role of Gift | 대화의 목적지가 아니라 단초. 사내 카페 쿠폰은 반값이라 쉽게 고르고, 쓰는 곳이 회사 안이라 마주칠 일이 생긴다 |

**하지 않는 것:** 팀 대화·팀 약속·공든 탑 / 관계 측정, 회사가 보는 데이터나 대시보드 / 세대·나이·연차·직급 라벨과 통계 / 정답 보상, 연속 기록, 순위 / 앱 안 채팅, 커피챗 예약, 읽음 표시 / 돌려주기 / 받는 사람에게 가격 표시 / 차단 설정 / 주말·공휴일 질문

**비즈니스 전제:** 회사가 도입한다. 선물 비용은 회사 복지 예산이고, 사내 카페와는 직원 선물 가격을 협의한다. 탑으로 내지 않은 금액은 모두 회사가 부담한다.

**포트폴리오에서 확인할 것 (사용성 테스트 관찰 포인트)**
1. 관문을 10초 안팎으로 지나는가
2. 결과 화면에서 "생각과 다르네"에 해당하는 반응이 나오는가
3. 받은 사람이 "왜 나한테?"를 부담이 아니라 호기심으로 받아들이는가
4. 보내는 사람이 사내 카페 상품을 먼저 고르는가

**나중 아이디어 (이번 범위 밖)**
- **가장 많이 대화한 사람 어워드와 보너스** (사용자 제안, 2026-10-03). 앱은 앱 밖의 대화를 알 수 없으므로, 실제로 셀 수 있는 것은 건넨·받은 조약돌 수다. 그것으로 순위를 매기면 '받은 개수 비교 안 함', '순위 없음' 원칙과 부딪히고, 상을 노리고 조약돌을 뿌리는 행동이 생길 수 있다. 진행한다면 개인 순위 대신 참여자 추첨이나 회사 행사 쪽을 검토한다.

## 2. Information Architecture (Phase 2)

### 2-1. 구조
- **시작** (S0): 사내 메일로 가입 → 관문·익명·근태 연결 안내 → 시작
- **오늘** 탭
  - S1 출근하기 / 퇴근하기
  - S2 관문 질문: a 내 답 → b 예상
  - S3 출근 완료 · 퇴근 완료: 조약돌 +1, 지난 질문의 결과
  - 지난 질문 모아보기 (S1 하단 링크)
- **조약돌** 탭
  - S4 내 조약돌: 쌓이는 중(n/10), 보유 탑, 받은 조약돌, 건넨 조약돌
  - S5 건네기: a 사람과 선물(스토어) → b 한마디
  - S6 받은 조약돌: 선물, 한마디, 화답
- **알림:** 조약돌 도착, 화답 도착 (질문 알림은 없다. 출퇴근 등록이 곧 계기)
- **설정**(오늘 탭 오른쪽 위 아이콘): 근태 연결 상태, 글자 크기

### 2-2. 화면 목록
| ID | 화면 | 들어오는 길 | 나가는 길 |
|---|---|---|---|
| S0 | 시작 | 첫 실행 | S1 |
| S1 | 오늘 (출근 전 / 출근 후) | 앱 실행, 오늘 탭 | 출근하기·퇴근하기 → S2, 지난 질문 모아보기 |
| S2-a | 관문 질문 · 내 답 | S1 | 보기 선택 → S2-b |
| S2-b | 관문 질문 · 예상 | S2-a | '출근 완료'·'퇴근 완료' → S3, 뒤로 → S2-a |
| S3 | 완료와 결과 | S2-b | 닫기 → S1. 탑이 완성된 등록이면 [조약돌 보기] → S4 |
| S4 | 내 조약돌 | 조약돌 탭, S3 | [선물 고르기] → S5-a, 받은 항목 → S6 |
| S5-a | 건네기 · 사람과 선물 | S4 | [다음] → S5-b |
| S5-b | 건네기 · 한마디 | S5-a | [탑 n개로 건네기] → S4 |
| S6 | 받은 조약돌 | 도착 알림, S4 | 화답 보내기 또는 닫기 → S4 |

## 3. 규칙과 User Flow (Phase 3)

### 3-1. 시스템 규칙
**근무일과 질문**
- 질문은 근무일(월~금, 공휴일 제외)에만 나온다. 하루에 출근 질문 하나, 퇴근 질문 하나.
- 출근 질문은 가벼운 개인 경험, 퇴근 질문은 서로를 궁금하게 만드는 질문으로 짝을 짓는다(4-3).

**관문**
- 순서: 출근하기 → 내 답 → 예상 → 출근 완료. 퇴근도 같다.
- 질문 화면에 건너뛰기 버튼이 없다. 마지막 버튼 이름이 '출근 완료' / '퇴근 완료'다.
- **출근·퇴근 시각은 '출근하기'를 누른 순간으로 기록한다.** 질문 도중 앱을 닫아도 기록은 남는다. 다시 열면 "09:02 출근이 기록돼 있어요. 오늘 질문은 퇴근할 때까지 열려 있어요" [지금 답하기].
- 근태 시스템 전송에 실패하면 질문으로 넘어가지 않고 다시 시도하게 한다.

**결과 공개**
- 출근 질문의 결과는 그날 퇴근 완료 때, 퇴근 질문의 결과는 다음 근무일 출근 완료 때 보여준다. 금요일 퇴근 질문은 월요일 출근 때.
- 마감 시간은 없다. 각자의 다음 등록 순간까지 모인 답으로 보여준다.
- 답이 10명보다 적으면 결과를 보여주지 않고 다음 등록으로 미룬다(익명 유지).
- 답하지 않은 질문의 결과도 볼 수 있다. '내 답 · 내 예상' 줄만 비운다.
- 결과에는 분포, 응답 수, 내 답, 내 예상, 실제 1위만 나온다. 결과를 해석하는 문장은 넣지 않는다.

**익명**
- 답과 예상은 누구에게도 이름과 함께 보이지 않는다. 회사도 볼 수 없다.
- 이름이 보이는 것은 조약돌을 건넬 때(보낸 사람)와 받은 사람의 화답뿐이다.

**조약돌과 탑**
- 관문을 지날 때마다 조약돌 +1. 하루 최대 2개. 정답 여부와 무관하다.
- 10개가 되면 탑 하나가 완성된다. 탑 하나 = 2,000원만큼. 탑은 '보유 탑'으로 옮겨지고 조약돌은 0부터 다시 쌓인다.
- 보유 탑은 여러 개 모을 수 있고 사라지지 않는다.

**스토어와 가격**
- 결제 금액: 사내 카페는 정가의 절반, 모바일 쿠폰은 정가.
- **필요한 탑 개수 = 결제 금액 ÷ 2,000원의 몫(내림).** 탑으로 내지 않은 나머지는 회사가 부담한다. 예: 4,500원 → 탑 2개 + 회사 500원.
- 스토어에는 결제 금액이 2,000원 이상인 상품만 둔다(탑 개수가 최소 1개).
- 보내는 사람의 스토어에는 탑 개수와 원래 가격이 보인다. 사내 카페는 정가에 취소선, 결제 금액을 함께 보여준다.
- 받는 사람에게는 상품 이름과 쓰는 곳만 보인다. 가격과 탑 개수는 보이지 않는다.

| 상품 | 구분 | 정가 | 결제 금액 | 탑 | 회사 부담 |
|---|---|---|---|---|---|
| 아메리카노 | 사내 카페 | 4,000원 | 2,000원 | 1 | 2,000원 |
| 차 한 잔 | 사내 카페 | 4,000원 | 2,000원 | 1 | 2,000원 |
| 조각 케이크 | 사내 카페 | 8,000원 | 4,000원 | 2 | 4,000원 |
| 음료 두 잔 | 사내 카페 | 8,000원 | 4,000원 | 2 | 4,000원 |
| 편의점 커피 | 모바일 쿠폰 | 2,000원 | 2,000원 | 1 | 0원 |
| 카페 아메리카노 | 모바일 쿠폰 | 4,000원 | 4,000원 | 2 | 0원 |
| 카페 라떼 | 모바일 쿠폰 | 4,500원 | 4,500원 | 2 | 500원 |
| 아이스크림 | 모바일 쿠폰 | 8,000원 | 8,000원 | 4 | 0원 |

**건네기와 화답**
- 받는 사람은 같은 회사 구성원 누구나다. 이름이나 부서로 찾고, 이름과 부서만 보인다.
- 한마디는 고를 수 있는 문장 넷(한번 이야기해보고 싶었어요 / 오늘 질문 보다가 생각났어요 / 늘 고마웠어요 / 직접 쓰기)과 직접 쓰기 40자. 문장을 고르고 직접 쓴 줄을 덧붙일 수도 있다.
- 받은 사람은 화답을 **한 번** 보낼 수 있다(고를 수 있는 문장 셋 + 직접 쓰기). 화답은 선택이다.
- 돌려주기 없음. 받은 선물은 내 조약돌이나 탑에 더해지지 않는다.
- 보낸 사람에게 읽음 표시는 없다. 화답이 오면 알림이 가고 '건넨 조약돌'에 표시된다.
- "답례하지 않아도 괜찮아요"를 보내는 화면과 받는 화면 모두에 적는다.

### 3-2. User Flow
**F1 첫 시작:** 사내 메일 초대 → S0(관문, 익명, 근태 연결 안내) → 시작하기 → S1. 첫 출근 완료 때는 지난 결과 대신 "첫 출근을 환영해요"가 나온다.

**F2 출근 (핵심):** S1 [출근하기] (시각 기록) → S2-a 내 답 → S2-b 예상 → [출근 완료] → S3 "출근 완료 09:02 ✓" · 조약돌 +1 · 어제 퇴근 질문의 결과 → 닫기 → S1(출근 후 상태, '퇴근하기')

**F3 퇴근:** F2와 같다. 결과는 오늘 출근 질문. 이 등록으로 탑이 완성되면 S3에 "탑 하나가 완성됐어요 · 2,000원만큼" [조약돌 보기].

**F4 탑으로 건네기:** S4 [선물 고르기] → S5-a 사람 찾기 → 상품 선택(보유 탑이 모자란 상품은 흐리게, "탑 n개 더 필요해요") → S5-b 한마디 → [탑 n개로 건네기] → 건너가는 모션 → S4(보유 탑 감소, '건넨 조약돌'에 추가)

**F5 받기:** 도착 알림("재무팀 Lucy님이 조약돌을 건넸어요", 미리보기에는 상품만) → S6 선물, 쓰는 곳, 한마디, "답례하지 않아도 괜찮아요" → (선택) 화답 한 번 → 끝

**F6 예외**
| 상황 | 처리 |
|---|---|
| 주말·공휴일 | S1에 "오늘은 쉬는 날이에요. 월요일 출근할 때 금요일 퇴근 질문의 결과가 열려요." 등록 버튼 없음 |
| 관문 도중 앱 종료 | 출근은 이미 기록됨. 다시 열면 [지금 답하기]. 그날 퇴근 관문 전까지 답할 수 있음 |
| 근태 전송 실패 | 질문으로 넘어가지 않음. "출근 기록이 회사 시스템에 전달되지 않았어요. 다시 시도해 주세요" |
| 답 저장 실패 | 고른 보기 유지, 다시 시도 |
| 결과 인원 10명 미만 | "아직 답이 모이는 중이에요. 다음 등록 때 보여드릴게요" |
| 보유 탑 없음 | S4의 [선물 고르기] 대신 "탑 하나까지 조약돌 n개 남았어요" |

## 4. Wireframe 기준 (Phase 4)

### 4-1. 기준
Lo-fi v0.3의 화면 7개(S0~S6)가 와이어프레임 기준이다. 아래 4-2와 5장의 조정이 우선한다.

### 4-2. v0.3에서 바뀌는 것
- 스토어의 카페 라떼(4,500원)는 탑 3개(올림) → **탑 2개, 차액 500원은 회사 부담**
- S5-a 상품 줄에 사내 카페는 '정가 취소선 → 결제 금액', 모바일 쿠폰은 정가를 작게 표시
- S6에 쿠폰 유효기간 한 줄(예: "11월 6일까지")을 추가한다. 실제 쿠폰의 기본 정보라 넣는다

### 4-3. 프로토타입용 질문 세트 (한 주)
시연은 월요일 출근부터 시작한다. 월요일 출근 때 열리는 결과는 지난주 금요일 퇴근 질문이다.

| 때 | 질문 | 보기 |
|---|---|---|

### 5-1. 프로토타입 시연 설계 (Phase 9 예정)
포트폴리오 웹 프로토타입은 실제 시간을 기다릴 수 없으므로, 폰 화면 바깥에 시연용 조작 패널을 둔다. 패널은 제품의 일부가 아니다.
- **시간 넘기기:** "다음 등록으로"(월 출근 → 월 퇴근 → 화 출근 …), "주말 보기"
- **사람 바꾸기:** Lucy(보내는 쪽) ↔ Julie(받는 쪽)
- **처음부터:** 진행 상태 초기화
- 데이터: 가상의 A사(구성원 약 200명), 4-3의 질문 세트, 질문마다 미리 정한 결과 분포. 서버 없이 브라우저에만 저장한다.
- 시연 경로: 월 출근부터 금 퇴근까지 열 번 등록 → 탑 완성 → Julie에게 사내 카페 아메리카노 → Julie로 바꿔 받기와 화답.

## 6. Phase 6로 가기## 6. Visual Direction (Phase 6)

**강가의 젖은 조약돌.** 실제 회사에서 매일 여는 근태 앱처럼 차분하고, 조약돌만 손에 잡힐 듯한 질감을 가진다.

- 바탕은 물안개 같은 차가운 회녹색, 글자는 깊은 강물색. 흔한 흰 바탕 + 파란 버튼 조합을 피한다.
- 2024년의 파랑과 크림을 이어받는다. 파랑은 젖은 돌의 짙은 청회색(river)이 되어 '출근하기' 돌 버튼과 주요 버튼에만 쓴다. 크림은 햇빛색(sun)이 되어 '새로 놓인 돌'과 '내 답' 표시에만 쓴다.
- 조약돌은 열 개가 모두 다른 돌색이고, 빛이 왼쪽 위에서 드는 음영을 가진다. 탑 모양 4-3-2-1은 모든 화면에서 같은 돌이 같은 자리에 놓인다.
- 출근하기 버튼은 사각형이 아니라 **젖은 큰 조약돌**이다. 퇴근 뒤와 주말에는 마른 돌(밝은 회색)로 바뀌어 누를 수 없음을 형태로 알린다.
- 카드 테두리는 결과, 쿠폰, 보유 탑처럼 독립된 대상에만 쓴다.

| sun / sun-tint | #EFD98C / #FAF2D2 | 새 돌, 탑 완성 빛 / '내 답' 태그 |
| 돌색 10개 | #B7B0A4 … #BCB3A5 | 돌마다 다른 색 |

- **글꼴:** 질문과 큰 순간(출근 완료, 받은 조약돌, 건넸어요)은 Hahmlet(한글 세리프), 나머지는 IBM Plex Sans KR. 숫자는 tabular.
- **크기:** 질문 27px, 완료 30px, 화면 제목 22~26px, 본문 15~16px, 설명 12.5~13px. 설정의 '크게'는 전체 1.1배.
- **줄바꿈:** 한국어는 단어 단위(`word-break: keep-all`).
- **터치 영역:** 44px 이상. 보기 버튼 60px, 주요 버튼 56px.
- **컴포넌트:** 돌 버튼, 보기 버튼(번호 + 답, 선택 시 테두리와 번호가 river-deep), 결과 카드(막대, 내 답·내 예상 태그, 비교 한 줄), 스토어 상품 줄(아이콘, 가격, 탑 개수), 고를 수 있는 문장 칩, 쿠폰, 알림 배너, 설정 시트.
